# モデル中心の課題スイート（設計判断の記録）

作成: 2026-10-19。研究の問いを「脆弱性検出」から **「CPG の構造情報を融合すると、コード LM は良くなるか。どんな条件で効くか」** に組み替えるための設計判断と、その根拠を記録する。数値には出典を付け、**本セッションで実測した値**と**文献値**を区別する。文献値は一次資料を読んだものと、検索抜粋からの転記（「未確認」）を分けて書く。

## 1. 問いと仮説

**問い。** C/C++ コードの単入力分類で、微調整した CodeBERT に Joern の CPG 枝（凍結 CodeBERT のノード特徴 → R-GCN（AST/CFG/PDG）→ 双方向クロスアテンション → ゲート）を足すと、(a) トークンのみのモデル、(b) 同じ融合器に**構造を壊したグラフ**を与えた対照、より良くなるか。良くなるなら、どの条件（ラベルの正確さ、クラス数、プログラム長、構造依存性）で差が出るか。

**仮説。**
- H1（必要条件）: hybrid が codebert と shuffle_edges 対照の両方に、対応つき bootstrap の 95% 区間が 0 を含まない差で勝つ。codebert には勝つが shuffle_edges に勝たないなら、利得は容量であって構造ではない。
- H2（構造依存性）: 利得は課題の構造依存性の順に並ぶ。
- H3（辺の種類）: 利得は CFG/PDG 辺が運び、AST だけでは出ない（CodeBERT 自体が AST をかなり符号化している: Wan ら 2022、構造プローブ Spearman 0.85。文献値）。
- H4（条件）: 利得は 512 トークン超の長いプログラムで大きく、ラベルノイズが増えると消え、正解率の天井に近づくと消える。

**文献が示す効果量の目安（文献値）。** 事前学習済み LM に明示的構造を足した利得は小さい: GraphCodeBERT のデータフローで MRR +0.02 / F1 +0.009（Guo ら 2021）、UniXcoder の AST で POJ-104 MAP@R +1.78、他は ≤0.2（Guo ら 2022）、DeepDFA + UniXcoder で BigVul F1 +1.35（Steenhoek ら 2024）。一方 seed による揺れは Devign で F1 標準偏差 2.2〜3.5、予測の 34.9% が seed で反転（Steenhoek ら 2023）。**卒論の 43.85 vs 45.74（差 1.9）はこの帯の中にある。**

## 2. 採用するデータセット

| データセット | 課題 | 粒度 | 規模（実測） | ラベルの由来と質 | 役割 |
|---|---|---|---|---|---|
| **BigVul**（既存） | 二値・不均衡（陽性 ~5%） | 単一関数 | 181k | 修正コミットの変更関数 = 脆弱。正確さ 54%（Croft ら 2023）/ 25%（Ding ら 2024）。文献値 | 元の設定。ノイズ最大の端点 |
| **CodeXGLUE Defect（Devign, FFmpeg+QEMU）** | 二値・ほぼ均衡（陽性 45.8%） | 単一 C 関数 | 21,854 / 2,732 / 2,732 | 同じ方式。正確さ 0.80（Croft、関数ラベルの正否）または 24%（PrimeVul、コミットがセキュリティ関連か）。**定義が違うので両方書く** | パイプライン無改変で動く二値の対照。トークン超過率 47〜50%（実測）が「被覆 vs 構造」の自然なレバー |
| **POJ-104** | 104 クラス・均衡（各 ~500） | プログラム全体（main + 補助関数 + グローバル配列） | 52,000（HF 版 53,000 から分割またぎの重複 1,000 行を除去） | 出題問題 ID。実質ノイズなし。完全一致重複 0.023%（実測） | ノイズなし・安価・飽和（ASTNN 98.09%、文献値）。低データ・ノイズ注入・長さ別の分析の基準 |
| **Project CodeNet C++1000** | 1000 クラス・均衡 | プログラム全体（現代 C++、template、#define、45% が複数関数） | 500,000（既定では 100/問題 = 100k に間引く） | 出題問題 ID。近似重複は配布時に除去済み（Jaccard 集合 0.9 / 多重集合 0.8） | **GNN が BERT 系に勝つと公表されている唯一の標準ベンチマーク**（C-BERT 93.79 vs GIN-V 96.64、論文 Table 10。文献値） |

採用の理由を一つずつ。
- **非セキュリティへ広げる最短経路は「プログラム全体の多クラス分類」。** C/C++ なので Joern の c2cpg がそのまま使え、単入力の分類ヘッドで済む。ラベルは出題問題 ID で人手ノイズがない。
- **POJ-104 は天井が近い（文献値 98%）。** それでも入れるのは、ノイズのない安価な基準点として、低データ領域・ラベルノイズ注入・長さ別評価の土台になるから。「差が出なかった」を「課題が構造を要らなかった」から切り分けるにはノイズのない課題が要る。
- **CodeNet は本命。** 既定の間引き（1000 問題 × 100 本 = 10 万本）は、公表値（50 万本）とは比較できない**院内比較**になる。これは明記する。クラス数 1000 を保つ方を選んだのは、クラス数が天井を決めるため（ランダム基準 0.1%）。
- **Devign は BigVul との連続性のために残す。** 均衡なので F1 が閾値に対して脆くない。

**不採用。** D2A（ラベル正確さ 29〜53%、重複 98%、テストラベル非公開）、ReVeal（配布コードが空白トークン化済みで `::` が `: :` に壊れ、同一関数 351 件が両ラベル、Joern 失敗 12.5%。すべて実測）、COFO（データ未公開）、BigCloneBench / Defects4J（Java、要フロントエンド切替）、DeepFix（構文エラーで解ける）、OpenCL DevMap（680 件）。PrimeVul はセキュリティ軸を残すなら BigVul の代替になる（重複 0%、正確さ 86〜92%。文献値）が、両腕とも F1 が 5 付近に落ちる（文献値）ので検出力がない。

**次の段階（未実装）。** 文献が「構造が効く」と予測する課題は VarMisuse 型（変数の取り違え検出: 構造を除くと 55 点落ちる。Chirkova & Troshin 2021、文献値）。C/C++ 版の公開データはなく、CodeNet/POJ から合成する生成器が要る。これが無いと「構造が要る課題では効くのか」に答えられない。

## 3. パイプラインの変更（この決定で入れる。実装は後続のコミット）

1. **多クラス分類**（`--num_classes`、`--embed` 時にラベルから推定して `input/manifest.json` に記録）。ヘッドの幅、focal loss の α（クラス数 C で `(1/C)/頻度`）、argmax の指標（accuracy / macro-F1 / top-5）、選択基準 `--select_on macro_f1|accuracy`、`compare_runs.py --metric macro_f1|accuracy`。**二値の経路はビット同一**（`tests/test_golden_binary.py` が凍結した出力と完全一致を確認する）。
2. **プログラム全体のグラフ**（`--graph_unit whole_file`）。Joern のファイル単位 `<global>` 疑似メソッドを採る。その AST はファイル内の全関数のノードを含み（実測: 固定データで 84 ⊃ 80 ノード）、グローバル変数とその初期化子も含み、`#define` の関数風マクロや呼び先スタブは含まない（実測）。これまでの「最初の非 `<global>` メソッドを採る」規則は、POJ で 15%、CodeNet で 44% のプログラムで main を捨てていた（実測、各 200 本）。
3. **ノード数の上限は位置順の切り捨て。** 上限に当たるとファイル後方の関数から消える。`graphs_at_cap` を manifest に記録する。CodeNet では `--max_nodes 1000` を推奨。
4. **拡張子の規則。** 前処理スクリプトが `ext` 列を書き、`to_files` がそれを優先する。K&R 形式の `main()`（戻り値型なし。POJ 訓練の 6%）を `.cpp` で渡すと main が丸ごと消える（Joern 4.0.400 で 6/6 実測）。逆に現代 C++ を `.c` で渡すと `using namespace std;` が UNKNOWN になるが main は残る。規則: **K&R main → `.c`、それ以外で C++ の手がかりがあれば `.cpp`**。BigVul の判定（`guess_extension`）は変えない。
5. **救済段階 C。** 小文字のシグネチャマクロ（`av_cold`、`coroutine_fn`、`APR_INLINE` など）と `MACRO(type)` 形の戻り値型を剥がす。Devign で 4.5%、D2A で 5.5% の関数がこれで Joern に落ちていた（実測、各 200 本）。
6. **データセットごとの安全装置。** `args.json` に dataset / data_root / num_classes / graph_unit / 入力 manifest を記録し、`--mode test` は data_root が違えば拒否する。run 名に `--run_prefix`。

## 4. 評価の手順（事前に決める）

- 分割は各データセットで 1 つに固定し、**学習より先にコミットする**（`*_prep_stats.json` と `classes.json` を含む）。
- 主比較は **5 seed 以上**（Steenhoek ら 2023 の分散なら、5 seed で平均の標準誤差 ≈ 1.1〜1.6 点。1〜2 点の効果を見るには 10 seed）。
- 判定規則: (i) 同じテスト集合上の対応つき bootstrap（seed 平均の差、≥10,000 回）の 95% 区間が 0 を含まない、かつ (ii) shuffle_edges 対照に対しても同じ、かつ (iii) 課題をまたいだ多重比較を Holm で補正。効果量は点差と seed 間の Cohen's d。
- 必須の対照: codebert（トークンのみ）、graph_only、hybrid-shuffle_edges（構造を壊す）、hybrid-no_gate、hybrid-no_cls_skip。将来: 辺種別の個別除去、次数保存のつなぎ替え、C 系で事前学習した LM への差し替え。
- 層別: トークン長（≤256 / 256〜512 / >512）ごとの利得。グラフ枝はプログラム全体を見るが、テキスト枝は 512 トークンで切れる（POJ 23〜33%、CodeNet 35%、Devign 47〜50% が超過。実測）。利得が >512 の層にしか無ければ「被覆」であって「構造」ではない。
- Joern で落ちた件数を分割・クラス別に記録し、**両腕を同じ生存集合で評価する**（既存の設計どおり）。

## 5. 既知の限界（審査で問われる点）

- CodeBERT の事前学習 6 言語に C/C++ は含まれない（Feng ら 2020、一次資料）。グラフ枝が「構造」ではなく「弱い LM の穴埋め」をしている可能性は、C 系で事前学習した LM（C-BERT / UniXcoder / CodeT5）への差し替えでしか排除できない。未実施。
- CodeNet の間引き版は公表値と比較不能。再現すべき院内基準線は codebert 腕そのもの。
- Devign のラベル正確さは定義で 80% と 24% に分かれる。両方を書き、ノイズ注入実験（0 / 10 / 25 / 45%）で挟む。
- POJ-104 配布版はプリプロセッサ行が削除され、9.7% のプログラムでコメントが `???` に化けている（実測）。コメントは前処理で除去する。
- CodeNet の「Accepted のみ」フィルタは論文に明記がない（論文 §5.3 は近似重複・デッドコード・パーサ通過の 3 条件のみ）。メタデータ（294 MB）を結合したときだけ status で絞れる。
- ライセンス: POJ-104 と CodeXGLUE は C-UDA、CodeNet は CDLA-Permissive-2.0（Linux Foundation の告知による。README・論文には記載なし）。
