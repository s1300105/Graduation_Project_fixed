# 研究設計: 効率的 attention は何を失い、何が安く取り戻すか

副題: 構造的事前分布による線形・SSM・疎の三系統の検証

## 0. 一文で

> 構造情報は、線形時間の attention / 状態空間モデル（SSM）が失った鋭さを安く取り戻す手段か。それはグラフの大きさと、構造がテキストと相補的かどうかに、どう依存するか。

検証可能な形に言い換えると次になる（第 2 回調査 §1.2、§2.2 を受けた版 0.4 の言い換え。「最も安い」という主張は、系列の局所性・ゲート・周期 softmax という安く強い回復手段が文献に揃っているため、同コスト比較の結果としてしか言えない）。

> 系列の局所性（softmax 窓）・データ依存ゲート・周期的な softmax 層と**同じ壁時計・メモリで比べたとき**、グラフ構造（辺）は線形 attention / SSM の鋭さをどれだけ戻すか。その回復量はグラフの大きさと、構造がテキストと相補的かどうかに、どう依存するか。

これは「GNN と LLM の融合」の研究ではない。**効率的な注意機構の性質**についての研究で、GNN 的な構造はその性質を調べる手段である。LLM は凍結したテキスト読み手として使い、効率の主張は融合経路のコストと入力トークン数に限定する。

研究は二本の柱からなる（版 0.5）。

1. **統制実験。** 凍結 LM の上に置いた融合層で、注意機構の形（softmax・線形・SSM・疎）と構造の入口を因子として振り、同じコストで鋭さの回復量を比べる（H1〜H4）。
2. **実在モデルの分析。** 公開されている線形・SSM・ハイブリッドの事前学習モデルの中で、鋭さと検索の失敗が長さとともにどう動くかを測る（H5）。柱 1 の指標をそのまま使い、統制実験の結論が実モデルでも見えるかを確かめる。

実装面では、φ の内部に構造を入れる線形 attention を自前の Triton カーネルで書く（公開実装が無いため。§12）。理論は軽めに一つ、線形 attention の長さ依存の分散の上界を任意の目標とする（§2 の末尾）。

## 1. 問いの背景（調査で確定した事実）

| 事実 | 出典 |
|---|---|
| 線形・カーネル化 attention は softmax に精度で劣る。失われるのは N ≫ d 個のキーから少数を選ぶ argmax 的な読み出しで、機構は三つ: 非負特徴写像による分布の一様化、attention 行列のランク ≤ d、固定サイズ状態による検索容量の Ω(N) ビット下界 | [GraphGPS](https://arxiv.org/abs/2205.12454)、[GraphTARIF](https://arxiv.org/abs/2510.10631)、[Hedgehog](https://arxiv.org/html/2402.04347)、[Based](https://arxiv.org/html/2402.18668v2)、[Repeat After Me](https://arxiv.org/html/2402.01032v2) |

## 2. 仮説と反証条件

記号: F = 注意機構の形（softmax / 線形 / SSM）、S = 構造の入口（なし / φ の外 / φ の内 / 厳密マスク）、T = データの型（必要 / 相補 / 導出可能）、L = 入力の大きさ。

**H1（回復）** 線形 attention に構造を入れると softmax との精度差が縮む。回復量は 厳密マスク ≥ φ の内（厳密な打ち切り冪級数） ≥ φ の内（GRF 近似） > φ の外 > なし の順。厳密版と GRF 版の差が、GRF の分散が回復量を食う量になる。
反証: 必要型のデータで、線形 ＋ φ の内（厳密） が差の 30% 未満しか回復しない。

**H2（事前分布か情報か）** 構造がテキストから導出可能な型では、softmax ＋ 構造 は利得を持たない（既知の否定結果と整合）が、線形 ＋ 構造 は利得を持つ。つまり構造は「情報」ではなく「鋭さの事前分布」として働く。
予測の表:

| | 導出可能型 | 必要型 |
|---|---|---|
| softmax ＋ 構造 | 利得なし | 利得あり |
| 線形 / SSM ＋ 構造 | **利得あり** | 利得あり、softmax との差が縮む |

反証: 導出可能型で 線形 ＋ 構造 − 線形 単体 の区間が分解能の中に収まる。この場合、構造は情報としてしか効かないという否定結果になる（それでも H1・H3・H4 は成立し得る）。

**H3（大きさ）** 固定サイズの状態による検索は、入力の長さ L が状態の容量を超えると失敗する（Ω(N) ビットの下界、S-NIAH の 4K → 8K での崩落）。構造は各クエリの実効支持を近傍の大きさ deg(v) に縮め、状態に要求される容量を下げるので、構造による回復量は L_t と N に増える。これは精度側の「大きさ」である。コスト側の「大きさ」（線形が壁時計で softmax に勝つ交差点）は別の量で、別に測る。
注: 「線形 attention の一様化（エントロピー）は長いほど悪化する」という形の法則は文献に無い（softmax には Θ(1/n) の定理があるが、線形には無い。Hedgehog は softmax との KL が 256〜4096 で一定と報告）。この前提は P4 で実測し、成り立たなくても H3 は検索容量の形で検定できる。
反証: 回復量が L に対して平坦で、**かつ**同じ長さで測った合成検索課題（「属性 X を持つノードはどれか」型）の正答率にも長さ依存が無い。

**H4（安いか）** 鋭さを取り戻す構造なしの手段、すなわち (a) 局所 softmax 窓 64 / 128 ＋ 線形大域（Based / LoLCATs 形）、(b) データ依存ゲート ＋ delta 則（GLA / GDN 形）、(c) 融合層 F 層のうち 1 層を全対 softmax にする周期ハイブリッド（F = 4 で 3:1、Kimi / Qwen3-Next 形）、(d) 特徴写像の鋭化（Hedgehog または Taylor 2 次）、(e) 学習で選ぶ疎な softmax（各クエリが上位 k 個のブロックだけを見る方式）と比べ、同じ壁時計・ピークメモリ・KV / 状態バイトの下で、構造の方が回復量が大きい。(e) は第 3 回文献調査で水準を確定する（§4.2、§13）。
文献の ablation は (a) が単独で最大の検索回復を与え、次に (b)、(d) は perplexity を戻すが検索は部分的、と一貫している。製品の線形 LLM が全てハイブリッドである事実は、帰無仮説「構造は鋭さの回復に必要ではない」を強く予想させる。
反証: (a)〜(c) のいずれかが同コストで同等以上。この場合「構造は鋭さの回復に必要ではなく、系列の局所性で足りる」が結論になり、それ自体が報告価値を持つ。

**H5（実在モデル）** 公開されている線形 attention・SSM・ハイブリッドの事前学習モデルでは、(i) 検索に使われるヘッドの正規化エントロピーが入力の長さとともに上がり、同じ長さで検索課題の正答率が落ちる。(ii) ハイブリッドでは、鋭い読み出し（低い正規化エントロピー、高い top-k 質量）が softmax 層と窓の層に集中する。同規模の softmax モデルと並べて比べる。
反証: (i) 長さに対して、鋭さの指標と検索の正答率が連動しない。(ii) 鋭い読み出しが softmax 層に集中しない。どちらも、統制実験で使う鋭さの指標が実モデルの失敗を説明しないことを意味し、H1〜H4 の解釈の範囲を狭める。

**H1〜H5 の全てで、精度だけでなく鋭さの指標（§3.1）が同じ向きに動くことを機構の証拠とする。** 精度だけなら相関の報告で終わる。

**任意の理論目標。** softmax には「有界ロジットなら長さ n で全ての重みが Θ(1/n) に落ちる」という定理があるが、線形 attention には無い（第 2 回報告書 §3.1）。特徴写像の値域や spikiness を条件にした、線形 attention の重みの長さ依存の上界と下界を示す。調査ノートには「カーネル値が [m, M] なら最大重み ≤ (M/m)/n」という推論があり、これを出発点にする。H3 の理論的な根拠になるが、修論の必須成果にはしない。

## 3. 操作化

### 3.1 鋭さ

融合層の attention 行列（線形 attention と SSM では、検証バッチの一部のクエリについて暗黙の重み φ(q)ᵀφ(k_j) / Σ_i φ(q)ᵀφ(k_i) を明示的に復元する）に対して、層ごと・ヘッドごとに次を測る。生のエントロピーは長さをまたいで比較できないので報告しない。支持の大きさは水準ごとに明記する（全対なら n、因果なら i、グラフなら deg(v)、整合マスクなら区間長）。

| 指標 | 定義 | 用途 |
|---|---|---|
| 正規化エントロピー Ĥ | H(A_i) / log(支持の大きさ) | 主指標（行方向） |
| 実効支持比 | exp(H) / 支持の大きさ。「実質的に見ているキーの割合」 | Ĥ の直感的な対 |
| 最大重み、top-k 質量 | max_j A_ij、固定 k の上位質量（自明下界 1/n、k/n を併記） | 行動指標との橋渡し |
| sink 質量 | 指定キー（CLS 型の読み出しトークン、仮想ノード、先頭）への平均質量と、Gu らの Sink_k^ε（ε = 0.3、T を明記） | 列方向。「中身のない鋭さ」を除外するために別途報告し、除外した上で Ĥ を再計算する |
| 実効ランク | erank = exp(H(σ / Σσ)) を attention 行列**と層出力**の両方に。同じ N でのみ比較 | GraphTARIF の定理と Dong らの残差に対応 |
| 構造質量 | 1-hop、2-hop、整合辺の上に乗る質量の割合（近傍サイズを併記） | 構造が読まれたか |
| 行動指標 | 合成検索課題（「属性 X を持つノードはどれか」型。MQAR / S-NIAH 相当）の正答率を長さ別に | 鋭さと精度の連鎖の証拠 |

全て長さ L_t とノード数 N で層別して報告する。学習の前後と、構造の有無で比較する。出典と各指標の由来は第 2 回報告書 §3.4。

### 3.2 大きさ

- 精度側: テキストトークン数 L_t とノード数 N。合成データでは生成時に制御し、実データでは長さ別の層に分けて報告する。同じ長さで合成検索課題の正答率を併記する（H3 の反証条件）。大きさの OOD（小さいグラフで学習し大きいグラフで試験）は CLRS の 16 → 64 ノードの形式を借りる。
- コスト側: 融合層の順伝播＋逆伝播の壁時計とピークメモリを、L_t ∈ {1k, 2k, 4k, 8k, 16k, 32k, 64k} × N ∈ {100, 300, 1k, 3k} で計測する（§6.2）。線形が softmax に勝つ交差点を報告する。

### 3.3 相補性（データの型）

型は著者の印象ではなく、各データセットで**事前に決めた規則**で測って割り当てる。

| 測る量 | 意味 |
|---|---|
| a. 素の GNN（構造とノードラベルのみ、テキストなし）の精度 − 偶然 | 構造だけで解けるか |
| b. テキストのみ（凍結 LM ＋ 線形分類）の精度 − 偶然 | テキストだけで解けるか |
| c. softmax ＋ 構造 の精度が、辺をシャッフルすると落ちる量 | 構造が実際に使われたか |

規則: b が a より十分高く c が分解能の中 → **導出可能型**。a が b より高いか c が大きい → **必要型**。a と b が同程度で、両方を合わせた softmax 腕が各単独を上回る → **相補型**。TAG では同類性とノードテキスト長も併記する。この割り当ては予備実験で行い、事前登録に固定する。文献にこの操作化は無く、これ自体が貢献になる。

## 4. モデル空間

### 4.1 共通の骨格

```
テキスト: 凍結 LM（§4.4 の規模系列） → 最終層の隠れ状態をキャッシュ → 線形射影 d
構造:     ノード = 構造の単位（AST ノード、グラフのノード）
          ノード特徴 = ラベル埋め込み ＋ 整合するトークンの隠れ状態の平均または attention プーリング（先頭サブワードは使わない。テキスト以上の情報を持たせない）
結合列:   [トークン列 ; ノード列]。関係種別 = 整合辺（トークン→所属ノード）、構造辺（AST 親子・兄弟・def-use、またはグラフの辺）、系列辺（隣接トークン）
融合:     結合列の上に F 層。各層 = 注意（§4.2 の形）＋ FFN ＋ 残差 ＋ LayerNorm
読み出し: マスク付き平均 → 分類器
```

整合の規則: 葉ノード ↔ サブワード区間（GraphCodeBERT 形）、内部ノード ↔ ソース範囲を最短で含むノード（Code Transformer 形）。ノードを列として入れ、区間マスクだけで学習させる無プーリング案は P1 の比較対象にする。

位置・構造符号化の既定: RRWP（(D⁻¹A)^k の積み重ね、K = 21〜32）を関係バイアスとして木と一般グラフの両方に固定し、ノード特徴だけで済む所は RWSE（対角）。理由は、符号・基底の曖昧さが無いこと、冪の積み重ねがスペクトル核と同等であること（Black ら）、GRF マスクが推定する対象 Σ θ_k W^k と同一物なので厳密版と GRF 版の比較が綺麗になること。LapPE / SPE は副次水準。N × N × K のメモリは実行時計算にする。構造信号はノード符号化をトークンに足すだけでなく、関係バイアスまたはマスクとして入れる。

今の `models/layers.py` の `FusionBlock`（code←graph と graph←code の 2 本の softmax cross-attention）は、この空間で「F = softmax、S = なし、support = 全対」の点であり、対照として残す。

### 4.2 因子 A: 注意機構の形 F

| 水準 | 実装 | 役割 |
|---|---|---|
| softmax | FlashAttention 2。加法バイアスとマスクは GDT の標準形 softmax(QKᵀ/√d ＋ B)V | コストの基準。「精度の上限」とは呼ばない（Kimi の 3:1 や GDN 1.3B のように、ハイブリッドや線形が softmax を上回る例があるので、対照が softmax を超える可能性を事前登録に書く） |
| 線形 | Performer 型の正のランダム特徴 φ（特徴数 r は予備実験で決め、全腕で固定）。累積は fp32（線形 attention は数値精度に敏感）。φ の内部に構造を入れる水準は自前の Triton カーネルで実装する | 本命 |
| 疎 | 各クエリが選んだ少数のキー（またはキーのブロック）にだけ softmax を掛ける。選び方は学習（上位 k 個のブロック選択）か構造（グラフ近傍のブロック）か両方。FlexAttention の BlockMask で実装し、ブロック疎性を記録する | 三つ目の系譜。「鋭さを保ったまま安くする」別解。具体的な方式（選択の学習法、ブロックの大きさ、k）は第 3 回文献調査で確定する |
| SSM | 作用素型、Chimera 形に確定。結合列 [トークン ; ノード] を一つの DAG（テキストは有向線グラフ、AST は親→子の有向辺、整合辺はトークン→ノード）とし、L = (I − A)⁻¹ の遷移をトポロジカル順の 1 パス O(\|V\| ＋ \|E\|) で計算する。一般グラフ（TAG、合成）は辺を 2 方向の DAG に分解するか直径で打ち切った Neumann 級数（二次）で近似し、その二次コストを §6.2 で測る。順序型（ノードを並べて走査）は使わない。状態追跡が要る課題では固有値域 [−1, 1] を任意水準に加える | 第 2 の本命（第 3 期）。「線形時間の別系譜でも同じか」 |

### 4.3 因子 B: 構造の入口 S

| 水準 | softmax での実装 | 線形での実装 | SSM での実装 |
|---|---|---|---|
| なし | 全対 | 全対 | 系列順の線グラフだけを A にした遷移 |
| φ の外 | 辺種別ごとの加法バイアス B（GDT 形） | 辺のある対にだけ疎な加法項（NodeFormer 形）。GraphTARIF 形の隣接を使う値側ゲートもこの水準 | Chimera の辺項 Δ′_ij |
| φ の内（厳密） | （定義なし） | 打ち切り冪級数 Σ_{k<K} α_k W^k を K 本の疎行列積で厳密に計算し、φ(q)ᵀφ(k) に要素積（N ≤ 10k で必ず置く。AST ではこちらが安く、精度も上回る見込み） | 隣接を A に入れる（Chimera 本来の形） |
| φ の内（GRF） | （定義なし） | トークン・ノードの φ に GRF をテンソル積で掛ける（GKAT、ICLR 2025 形）。トークンは整合先ノードの GRF を継承する。既定: 対称正規化 w_ij = 1/√(d_i d_j)、重要度重み必須、n = 100 本、p_halt = 0.1、最大長 100、反対称打ち切り、AST では縫合 l を P5 で掃引 | （定義なし。GRF は N × N マスクを実体化できないときの近似なので、SSM 側には対応物を置かない） |
| 厳密マスク | 支持外を −∞（FlexAttention） | 支持外を厳密に 0 にした低ランク（木・格子では ICML 2022 の手法で線形時間、一般グラフでは上限参照として二次で計算） | 対照は同じ隣接上のマスク付き softmax（「線形マスク＋状態」対「softmax＋明示的な対スコア」の分離） |

主効果と、F × S の交互作用（特に 線形 × φ の内）が H1 の検定対象。SSM 列では 3 水準が同一実装の A の違いになる。

疎の列（表に入れず別に定める）: 「なし」= 学習で上位 k 個のブロックを選ぶ、「構造で選ぶ」= 整合辺と構造辺で到達できるノードを含むブロックを選ぶ、「併用」= 両方の和集合。疎で構造が勝つかは「学習による選択」と「構造による選択」を同じ k で比べることになり、H4 の (e) と表裏一体である。

### 4.4 因子 C: 構造なしの鋭さ回復（H4 の対照）

線形 attention に対してのみ。各水準は壁時計・ピークメモリ・KV / 状態バイトを 線形 ＋ φ の内 と ±10% に揃える（パラメータ一致だけでは窓の対照が有利に見える）。文献の ablation で強い順に次の 4 水準。

- (a) 局所 softmax 窓 w ∈ {64, 128} ＋ 線形大域（Based / LoLCATs 形、全融合層）。文献上、単独で最大の検索回復。
- (b) データ依存ゲート ＋ delta 則（GLA / Gated DeltaNet 形）。状態側の鋭さの回復。
- (c) 周期ハイブリッド: 融合層 F 層のうち 1 層を全対 softmax（F = 4 で 3:1。製品の最頻比）。
- (d) 特徴写像の鋭化: Hedgehog の exp-MLP か Taylor 2 次（特徴数を揃える）。
- (e) 学習で選ぶ疎な softmax（上位 k 個のブロック選択）。k は 線形 ＋ φ の内 と壁時計が揃うように決める。

版 0.3 にあった「ランク回復ゲート（GraphTARIF 形）」は隣接を使う GAT 分岐なので構造なしではなく、S = φ の外に移した。構造なしのランク回復（FLatten の深さ方向畳み込み、MHLA のトークン分割）と Gumbel 疎化は任意水準に落とす（新しい支持証拠が無い）。

### 4.5 否定結果から要求される必須の対照

| 対照 | 守る主張 | 出典 |
|---|---|---|
| テキストのみ（凍結 LM ＋ 線形分類、同じキャッシュ） | 構造の利得がテンプレートや容量の差でない | [When Structure Doesn't Help](https://arxiv.org/html/2511.16767v2) |
| 学習済み定数トークン（構造を見ない追加列） | 追加列の存在そのものの効果を除く | [Token Collapse](https://arxiv.org/html/2610.31572) |
| 直列化した構造をテキストとして LM に LoRA で学習（トークン予算を揃える） | 「GNN 経路 対 直列化」の公平比較 | [G-Retriever](https://arxiv.org/html/2402.07630v3)、[Less is More](https://arxiv.org/html/2508.10115v1) |

### 4.6 揃える規則

- 学習可能パラメータ数は同じ F の中で ±5%。F をまたぐ比較と因子 C の比較はパラメータではなく壁時計・ピークメモリ・KV / 状態バイトで揃え、全てを報告する。
- 学習ステップ数、データ、seed、最適化設定は全腕で同一。
- 凍結 LM は全腕で同じキャッシュを読む。LM の中に LoRA を入れるのは「直列化 LoRA」対照だけ。

### 4.7 テキスト側 LM

- 族は 1 つに絞る（版 0.5）。候補は Qwen2.5 の 0.5B / 1.5B / 3B（同一族で規模を振れる。コードと一般テキストの両方を読める）と Llama-3.2 の 1B / 3B（GTLM との対置に有利）。どちらにするかは §13 項目 1。
- 規模系列は同じ族の 3 点まで。版 0.4 にあった 7B と 2 族目は削った。注意機構の研究としての主張には効きにくく、計算量が大きいため。時間が余れば第 4 期に 7B を 1 点だけ足す。
- 版 0.4 で第 3 期に置いた「Mamba 系 LLM をテキスト側に置く拡張」は、§6.5 の実在モデルの分析に置き換えた。分析には学習が要らず、推論だけで済む。候補モデルは §6.5。

## 6. 測定

### 6.1 精度と効率の前線

- 精度: 課題ごとの標準指標（accuracy / macro-F1 / ROC-AUC / 回帰は MAE）。
- 効率: 学習 1 ステップと推論 1 サンプルの壁時計、ピークメモリ、入力トークン数（直列化腕）。FLOPs は副。
- 報告の形: 前線を 3 枚組で描く。精度 対 log(状態サイズまたはピークメモリ)（Based 形）、精度 対 FLOPs、精度 対 壁時計（Mamba-2 / Griffin 形）。FLOPs と壁時計の乖離自体を結果にする。同一バックエンド比較（FlexAttention 同士）と異バックエンド比較（FlashAttention 2 対 Triton）を両方載せ、実装成熟度の偏りを宣言する。同一ハードウェア（RTX 3090、24 GB）で全て測り、その旨を明記する。
- 前処理コスト（最短路、GRF のランダムウォーク、固有分解）も計上する（[OpenGT](https://arxiv.org/html/2506.04765) の報告に倣う）。

### 6.2 マイクロベンチ

融合層単体で、L_t × N の格子上で順伝播＋逆伝播を計測する。手順は固定する。

- 計測は Triton の `do_bench`（warmup ≥ 100 ms、L2 キャッシュのクリア、CUDA event、中央値と 20 / 80 分位）。1 点を `torch.utils.benchmark.Timer` で検算。ライブラリ版・ドライバ・電力上限・温度状態を記録し、クロック固定が可能なら試す。
- 格子は FlashAttention 2 の慣行（バッチ × 系列長 = 16k トークン固定、512 → 16k の倍々）に、**短系列帯 128〜2048 を必ず加える**。文献上そこでは線形・SSM が FlashAttention 2 に負ける（GB200 でも T ≤ 2048 で FA2 が速い）。
- softmax は FlashAttention 2、マスクつき softmax は FlexAttention（BlockMask の構築コスト、キャッシュ、ブロック疎性、compile のウォームを記録）。**FlexAttention-dense（何もしないマスク）腕を置いて**、カーネル差とマスク費用を分離する。線形は自前の φ 実装（fp32 累積）、SSM は選択的走査または Chimera 形の DAG パス。状態サイズとチャンクサイズを記録。
- FLOPs は FA2 の式（4·B·L²·H·d、因果で半減、逆伝播 ×2.5）で、因果半減の有無を明記。ピークメモリは `reset_peak_memory_stats` 後の `max_memory_allocated`。
- 交差点の長さは文献を引かず自分で測る（RTX 3090 / 4090 の一次資料は存在しない）。GTLM の「2 倍のステップコスト」と同種の数字をこちらでも出す。

### 6.3 学習曲線（データ効率）

学習データの幾何格子 1/16、1/8、1/4、1/2、1 で、主要な腕（softmax なし・softmax 外・線形なし・線形内・テキストのみ・因子 C の (a)）を回す。各サイズで学習率を再調整し、最小サイズで冪則から外れたら再調整する（Hestness）。曲線に POW3（a·n^−b ＋ c）を当て、「全データ精度の 90% に要するデータ量」を bootstrap 区間つきで読む。曲線下面積は曲線と併記するときだけ出す（交差を隠すため単独では出さない）。

### 6.4 規模系列

テキストのみを同じ族の 3 点（例: 0.5B / 1.5B / 3B）で、最小規模 ＋ 構造 と同じ図に載せる。「小さい LM ＋ 構造 が 大きい LM 単体 に届くか」は、同一族・同一データ・同一トークン予算でのみ主張する。

### 6.5 実在モデルの attention 分析（H5）

学習はせず、推論だけで測る。

- **対象。** 線形・SSM・ハイブリッドの公開モデルと、同規模の softmax モデル。候補は Mamba-2 の 130M〜2.8B、flash-linear-attention が公開する小型の Gated DeltaNet / GLA、ハイブリッドの Falcon-H1 1.5B、Hymba-1.5B。比較の softmax 側は同じ学習データ・同規模のものがあればそれを選ぶ（Mamba-2 と同じ Pile で学習した Pythia など）。最終的な一覧は第 3 回文献調査と P10 で決める。
- **課題。** 長さ別（1K / 2K / 4K / 8K / 16K）の合成検索課題（S-NIAH 型、MQAR 型、電話帳型）と、§5 の合成グラフを直列化した文章での属性検索。
- **指標。** §3.1 の表をそのまま使う。線形 attention と SSM は暗黙の重みを復元する（Mamba-2 は双対形式で L ⊙ CBᵀ を明示できる）。層ごと・ヘッドごとに、検索の成否で条件づけた指標を出す。sink 質量は必ず別に報告する。
- **出力。** 「鋭さの指標 対 長さ」と「検索の正答率 対 長さ」を同じ図に重ねる。ハイブリッドでは層の種類（softmax / 窓 / 線形・SSM）ごとに分けて描く。
- **計算量。** 3B 以下を 4bit で推論するだけなので、RTX 3090 1 枚で足りる。16K の長さでは暗黙の重みの復元をクエリの標本に限る。

## 7. 統計と事前登録

- 主比較（H1 の 線形＋φ内 − 線形なし、H4 の 対 窓）は **10 回の対応ある反復で、各反復で分割と初期化を再抽出する**（分割の分散が初期化の分散を上回るという Bouthillier らの結果、seed 5 では小差を主張できないという Henderson ら・Agarwal らの結果による）。副比較は seed 5 で、「小差は見分けられない」と事前登録に書く。
- 決定則は Bouthillier らの P(A > B)（γ = 0.75）か Wilcoxon ＋ Holm。項目単位の指標はテスト項目の対応つき bootstrap と、seed × 項目の二段 bootstrap（`scripts/compare_runs.py --seed_bootstrap`）。
- 各腕の調整予算を Dodge らの期待検証性能 対 予算 の曲線で公開する。
- 主比較は仮説ごとに事前に固定し、仮説の族の中で Holm 補正する。
  - H1: 線形＋φ内 − 線形なし、および (線形＋φ内 − 線形なし) / (softmax外 − 線形なし) の回復率。
  - H2: 型 × 形 の交互作用。導出可能型での 線形＋構造 − 線形なし を主、softmax＋構造 − softmax なし を副。
  - H3: 回復量の L に対する傾き（合成データ）と、同じ長さでの合成検索課題の正答率の長さ依存。
  - H4: 線形＋φ内 − 構造なし回復手段の最良。同コストの対。
- 分解能（95% 区間の半幅）を予備実験で見積もり、それより小さい差は「見分けられない」と書く。化学の事前登録（`docs/CHEM_PROTOCOL_ja.md`）と同じ運用。
- 本実験の前に事前登録文書をコミットし、予備実験は探索と明記する。形式は「提案 → 結果」の二段（NeurIPS 事前登録ワークショップの形式）で、結果文書は提案文書を書き換えずに追補する。

## 8. 予備実験（2〜3 週間）と中止基準

| 内容 | 規模 |
|---|---|
| 合成グラフ 1 課題（最短路長）× 2 サイズ、POJ-104 ファイル全体 | 2 データ |
| 腕: softmax なし / softmax 外 / 線形なし / 線形外 / 線形内 / 厳密マスク、テキストのみ | 7 腕 × 1〜2 seed |
| 測るもの: 精度、§3.1 の鋭さ（長さ 256 / 1K / 4K / 8K × N = 50 / 500 / 5,000 で層別）、合成検索課題の正答率、壁時計 | |

中止・変更の基準:

- 必要型で 線形＋φ内 が差の 30% 未満しか回復しない → GRF の分散（§10）を疑い、特徴数・重要度重み・GRFs++ 型の縫合を試してから規模を広げる。
- 導出可能型で 線形＋構造 の利得が分解能の中 → H2 は否定で確定とし、重心を H1・H3・H4 に移す。計画は続行。
- 壁時計の交差点が 64k トークンを超える → 実データの大きさでは効率の主張が成り立たないので、合成データのサイズ帯を上げるか、効率の主張をトークン数に限定する。

## 9. 計算資源と日程（締切まで約 18 か月）

第 1 期を 6 か月取る理由: 本実験の設計ミス（因子水準の選び違い、指標の不備、GRF の設定ミス、型の割り当て違い）は第 2 期以降に見つかると最も高くつく。第 1 期で潰す。執筆は第 2 期から並行して始めるので、第 4 期は短くて済む。

- GPU: 全期を通して RTX 3090 1 枚で足りる見込み。主実験 250〜400 GPU 時間、主比較の 10 反復で 100〜200 時間、実在モデルの分析（推論のみ）で数十時間。3B の LoRA 対照だけは 24 GB に収まらなければクラウド（A100 で 100〜200 ドル）を使う。
- ストレージ: 凍結 LM のキャッシュは整合ノード単位にプールして保存する（トークン全部を保存すると 1 件 8 MB、全体で 500 GB になる）。LM 1 族 × 規模 3 点なので 200〜300 GB の SSD で足りる。
- 文献の再調査を第 2 期末と第 4 期初めに行う。今回の調査でも 2026 年に近い先行（Tabula RASA、GTLM、GaLA）が複数出ており、この分野は月単位で動く。特に「構造つき線形 attention と LM の接続」「グラフ SSM と LLM の融合」の 2 つの空白が埋まっていないかを確かめ、埋まっていれば位置づけを書き直す。
- 期の順序を守る理由: 第 2 期の結果を外に出して査読を受けることで、第 3 期の追加が「査読で求められたもの」に向く。先に全部を回すと、手戻りが一番高くつく時点で指摘を受けることになる。

## 10. 技術的リスクと対策

| リスク | 根拠 | 対策 |
|---|---|---|
| GRF は疎で直径の大きいグラフで分散が大きく、歩みが交わらない対にゼロを返す。AST は木なのでまさにこの条件 | [Topological Masking](https://arxiv.org/html/2410.03462v2)、[GRFs++](https://arxiv.org/html/2510.07716v1) | 重要度重みつき GRF を必須にする（重みなしは無マスクより悪化した報告あり）。歩数と本数を予備実験で掃引。GRFs++ の縫合を実装候補に |
| テンソル積で特徴幅が d_s × d_g になる | 同上 | GRF を疎に保つ。アンカー点方式（KDLGT 形）を代替に |
| softmax 側は FlashAttention で実測が速く、線形が壁時計で勝つのは長い系列だけ | [GTLM](https://arxiv.org/html/2605.10247) | 交差点を測って報告する。FLOPs で勝ったと言わない |
| SSM 順序型は順序に敏感 | [Chimera](https://arxiv.org/html/2510.12111v1) | 作用素型のみ使う。順序型は入れない |
| ソフトトークンの崩壊（定数で置換可能） | [Token Collapse](https://arxiv.org/html/2610.31572) | 定数トークン対照を常に置く。構造は列として入れ、プールしない |
| 構造バイアスの種類で結果が逆転する（SPD が無効な場面） | [GTLM](https://arxiv.org/html/2605.10247)、[Attending to GTs](https://arxiv.org/abs/2302.04181) | φ の外の水準は辺種別バイアスと距離バイアスの 2 種を用意し、予備実験で選ぶ |
| 融合層だけの効率化では「LLM の効率化」と言いにくい | 報告書 §5 | 主張を「構造つき入力に対する融合経路のコストとトークン数」に限定して書く。Mamba 系 LLM は拡張 |
| 構造なしの回復手段（窓・ゲート・周期 softmax）が安く強く、構造の利得が消える | 第 2 回報告書 §1.2、§2.2 | H4 の対照に全て入れ、帰無仮説を事前登録に明記。消えた場合は「系列の局所性で足りる」という結論として報告する |
| 線形 attention は数値精度に敏感（MiniMax、RWKV-7 のカーネル） | 第 2 回報告書 §1 | 融合層の φ は fp32 累積。bf16 との差を予備実験で記録 |
| ICLR 2025 の位相マスクと GRFs++ の公開実装が無い | 第 2 回報告書 §4.1 | 自前実装。再現の定義は ViT の ImageNet 数値ではなく、1-D 格子の FLOPs 実験と小さな格子グラフでの厳密対 GRF 誤差 |
| FlexAttention はブロック疎性が無いと速くならず、要素ごとのマスクで 15〜20% の費用 | 第 2 回報告書 §5.1 | ブロック疎性を記録。FlexAttention-dense 腕でマスク費用を分離 |
| CLS 型の読み出しトークンや仮想ノードが sink になり、偽の鋭さを作る | 第 2 回報告書 §3.2 | sink 質量を別途報告し、除外して Ĥ を再計算 |
| tree-sitter の C/C++ はマクロと `#if` で ERROR ノードや誤解析を生む | 第 2 回報告書 §4.3 | `has_error()` と ERROR / MISSING 数を manifest に記録し閾値で除外。既知マクロはスタブしてから解析。失敗を空グラフにしない |
| 融合層をスクラッチ学習すると構造差を過大評価し得る（Amos ら） | 第 2 回報告書 §5.2 | 凍結 LM のキャッシュ上で融合層のみ学習する設計に加え、denoising 事前学習つきの対照を 1 本置く（§4.5） |
| 短系列では線形・SSM が FlashAttention 2 に負け、交差点が実データの長さの外に出る | 第 2 回報告書 §2.5、§5.1 | P8 で短系列帯を含めて測り、外に出るなら効率の主張をトークン数と大きい合成データに限定する |
