### 2.4 やり方

- 被引用の走査は Semantic Scholar の API キーを取得して行い、OpenAlex を併用する。題名だけでなく要旨まで読んで判定する。
- 論文ごとに次を記録する: 構造の入口（スコア / support / 正規化 / 値 / PE / φ 内 / SSM 作用素）、LM の有無と規模、揃え方（パラメータ・計算・トークン）、効率の軸、否定結果の有無、再現可能性（コードと重みの有無）。
- **再現対象**を選ぶ: 第 1 期で手元で再現する先行は 3 つ。ICLR 2025 の位相マスク（φ 内の回復。公開実装が無いので自前実装になる。再現の定義は ViT の ImageNet 数値ではなく、論文の 1-D 格子の FLOPs 実験と、小さな格子グラフでの厳密カーネル対 GRF の誤差）、GraphTARIF の診断（一様化・低ランク化）、When Structure Doesn't Help の否定結果（テキストのみ対照の強さ）。再現できない先行を基準にしてはいけない。
- **第 1 回・第 2 回の結論が変わった点**を分類表に反映する: 線形 attention の損失原因は「一様化・ランク ≤ d・検索容量」の三つ、SSM 融合で線形時間が成り立つのは DAG 上の Chimera 形のみ、GraphTARIF のゲートは構造あり、2026 年の構文 LM 研究は H2 の softmax 行を言語側から支持。
- 生きた分類表は 1 枚の表として保守し、新しい論文はまずそこに行を足す。

## 3. 予備調査（P1〜P9）

各項目に「目的」「方法」「決めること」を置く。順番は依存関係順。全て RTX 3090 1 枚で回る規模にする。

### P1. 構造抽出と整合の品質（第 1 か月）

- 目的: tree-sitter の AST と def-use が、全ファイルで決定的に取れ、トークンとノードの整合が壊れないことを確かめる。
- 方法: POJ-104 と CodeNet C++ の全ファイルで抽出。失敗率、ノード数とトークン数の分布、整合できないトークンの割合、関係ごとの辺数。LM のトークナイザとの境界ずれを数える。
- 決めること: 関係の種類（4 種で足りるか）、ノードの粒度（全 AST ノードか、文・式レベルに潰すか）、整合の規則。

### P2. 凍結 LM のキャッシュと「テキストのみ」の床（第 1〜2 か月）

- 目的: 否定結果（When Structure Doesn't Help）どおり、テキストのみの対照がどれだけ強いかを、使う全データで先に知る。
- 方法: 主系列 LM の 0.5B / 1.5B で全候補データの隠れ状態をキャッシュし、線形分類器と小さな MLP で精度を測る。保存形式（整合ノード単位のプール）の容量と読み込み速度も測る。
- 決めること: 保存する層（最終層か、中間層も要るか）、プール法、キャッシュの容量計画。

### P3. 相補性の型の割り当て（第 2 か月）

- 目的: 設計書 §3.3 の規則で、候補データの型を測って決める。
- 方法: 各データで (a) 素の GIN、(b) テキストのみ、(c) softmax ＋ 構造 と辺シャッフルの差を測る。TAG は同類性とテキスト長を併記。
- 決めること: 3 型それぞれに最低 2 データが入るか。入らなければ「識別子マスク」「テキスト削減」の操作で相補型を作る量を決める。

### P4. 鋭さの指標の妥当性（第 2〜3 か月）

- 目的: エントロピー・実効ランク・構造質量が、softmax と線形の差を実際に捉えることを確かめる。
- 方法: 同じデータで softmax と Performer 型線形の融合層を学習し、設計書 §3.1 の表の指標（正規化エントロピー、実効支持比、top-k 質量、sink 質量、実効ランク、構造質量）を層ごとに測る。**長さ 256 / 1K / 4K / 8K × N = 50 / 500 / 5,000 で層別**し、softmax 対線形の正規化エントロピー差が長さで開くかを測る。文献にはこの曲線が無い（線形 attention の分散の定理は存在しない）ので、この実測自体が H3 の前提の判定になる。同じ長さで合成検索課題（「属性 X を持つノードはどれか」型）の正答率を併設する。GraphTARIF の診断の再現に当たる。
- 決めること: 主指標をどれにするか。線形 attention で暗黙の重みを復元するクエリの標本数。sink になるトークン（読み出しトークン、仮想ノード）の扱い。H3 を「エントロピー」と「検索容量」のどちらの形で主に書くか。

### P5. φ 内の構造の実装と GRF の分散（第 3〜4 か月）

- 目的: GRF のテンソル積が木（AST）と合成グラフで使えるかを、精度の前に数値的に確かめる。
- 方法: 厳密な打ち切り冪級数 Σ α_k W^k（疎行列積）と GRF 近似の相対誤差を、本数 n・p_halt・最大長・重要度重みの有無・反対称打ち切りの有無・縫合 l・AST の深さ別に測る。出発点は ICLR 2025 の設定（n = 100、p_halt = 0.1、最大長 100、対称正規化）。ゼロ推定になる対の割合（距離 r の対の被覆確率は p_next^(r−2) で落ちる）。テンソル積の特徴幅と速度。厳密版の計算時間とメモリ（N = 300 / 1k / 3k / 10k）。
- 決めること: GRF の設定（全腕で固定する値）と縫合 l。AST（N ≤ 10k）では厳密版を主にし GRF を副にするか。重要度重みなしの GRF が無マスクと同等になる（ICLR 2025 の 0.689 対 0.693）ことの再現。

### P6. 回復の予備確認（第 4 か月）

- 目的: H1 の核心（線形 ＋ φ 内 が softmax との差を回復するか）を、小さい規模で先に見る。ICLR 2025 の結果のグラフ版の再現。
- 方法: 合成グラフ 1 課題 × 2 サイズと、POJ-104 ファイル全体で、softmax なし / softmax 外 / 線形なし / 線形外 / 線形内 / 厳密マスク の 6 腕、seed 2。
- 決めること: 設計書 §8 の中止基準の判定。回復率が 30% 未満なら P5 に戻る。

### P7. 構造なしの回復手段の予備比較（第 4〜5 か月）

- 目的: H4 の対照（(a) 局所 softmax 窓 64 / 128、(b) ゲート ＋ delta 則、(c) 周期ハイブリッド 3:1、(d) 特徴写像の鋭化）を、同コストに揃えられるかと、どれが強いかを見る。文献の順（(a) > (b) > (d)、(c) は少数層で足りる）が再現するかも確かめる。
- 方法: P6 と同じデータで 4 水準。壁時計・ピークメモリ・KV / 状態バイトを 線形＋φ内 と ±10% に揃える手順を作る（パラメータ一致だけでは窓が有利）。
- 決めること: 本実験に入れる水準（4 つ全部か、強い (a) と (c) の 2 つか）と、揃え方の規則。(a) が 線形＋φ内 と同等以上なら、本実験の帰無仮説として事前登録に明記する。

### P8. 壁時計の交差点（第 3 か月、P4 と並行）

- 目的: 線形・SSM が softmax（FlashAttention 2 / FlexAttention）に壁時計で勝つ系列長を、この GPU で知る。
- 方法: 設計書 §6.2 の手順（`do_bench`、FA2 の 16k 格子 ＋ 短系列帯 128〜2048、FlexAttention-dense 腕、ブロック疎性の記録）でマイクロベンチ。Mamba 系の走査と Chimera 形の DAG パスも含める。実装の最適化度の差（自前の φ 対 最適化された softmax カーネル）を明記する。
- 決めること: 合成データのサイズ帯と、実データで「大きい」とする閾値。交差点が 64k を超えるなら効率の主張の範囲を見直す。

### P9. 分解能の見積もり（第 5 か月）

- 目的: 本実験で見分けられる最小の差を、事前登録に書く。
- 方法: P6・P7 の結果で、主比較は 10 回の対応ある反復（分割と初期化を再抽出）、副比較は seed 5 を仮定して、二段 bootstrap の 95% 区間の半幅と P(A > B)（γ = 0.75）の分解能を見積もる（`scripts/compare_runs.py --seed_bootstrap`）。
- 決めること: 各仮説の主比較に対する分解能。それより小さい効果は「見分けられない」と事前に書く。10 反復の計算量が第 2 期の予算に収まるか。
