## Key Question 1 — Graph Random Features (GRFs) and topological masking in practice

### Takeaway
GRFs are unbiased random-walk estimators of any power series `K_α(W)=Σ_k α_k W^k` of a (normalised) adjacency matrix; the ICLR 2025 topological-masking paper is the only one in the lineage with an exponential concentration bound, and that bound depends on degree/edge-weights/p_halt only through a constant `c = Σ_k |f_k| (max|W_ij| d_i /(1−p_halt))^k` and not on N. The main practical failure mode for trees and sparse high-diameter graphs is the **zero estimate for node pairs whose walks never intersect** (probability of covering distance r decays like `p_next^(r−2)`); the lineage's mitigations are importance sampling (essential — removing it erases all gains in the ICLR 2025 ablation), more walkers, antithetic termination (q-GRFs), repelling walks, and walk stitching (GRFs++). Reported settings: p_halt ∈ {0.1, 0.5}, walkers n ∈ {4, 16, 20, 27, 100, 256}, max walk length 10–100.

**Exact mechanism / formulas**
- Base GRF (Choromanski ICML 2023, Alg. 1): for each node i run m walks; each walk starts with load 1, terminates before each step with probability p_term; at each step the load is multiplied by `u_{v,w} / (p(1−p_term))` (p = uniform neighbour-choice probability, i.e. 1/deg) and the load is added to the feature entry of the visited node; final vector divided by m. Expected walk length is 1/p_term. For the regularised Laplacian kernel `(I+σ²L̃)^{-1}` set `u_ij = σ²/(σ²+1) · W_ij/√(deg i deg j)` so that `I+σ²L̃ = (σ²+1)(I−U)` and the kernel is a Neumann series in U. d=2 (squared inverse) uses two independent feature sets; higher d recursively. — [ar5iv 2305.00156](https://ar5iv.labs.arxiv.org/html/2305.00156)
- u-GRFs (ICLR 2024, Alg. 1): walker starts load 1, moves to a uniform neighbour, load ← load × `d[current]/(1−p_halt) × W[current,new]`; at every visited node v adds `load × f(walk_length)` to `φ_f(i)[v]`; halts w.p. p_halt per step; divide by m. `φ_f(i) ∈ R^N`, `K̂_ij = φ_{f1}(i)ᵀ φ_{f2}(j)`. Unbiased for `K_α = Σ α_k W^k` iff α is the discrete convolution of f1 and f2: `Σ_p f1(k−p) f2(p) = α_k`. With f1=f2=f the recursion is `f(0)=±1, f(i+1) = (α_{i+1} − Σ_{p=0}^{i−1} f(i−p) f(p+1)) / (2 f(0))`; closed forms exist for d-regularised Laplacian, p-step random walk and diffusion kernels (inverse-cosine kernel is the noted exception). The matrix product must be computed as `φ1(φ2ᵀ v)` to stay O(N²). The modulation function may be a small 1-hidden-layer NN trained on Frobenius error; it converges to a *biased* f with lower MSE and approaches the unbiased f as m grows. — [arXiv HTML 2310.04859v3](https://arxiv.org/html/2310.04859v3)
- Topological mask (ICLR 2025): `M_α(G) = Σ_k α_k W^k` with learnable Taylor coefficients α_k; common choice `w_ij = 1/√(d_i d_j)`; M is PD iff `Σ_k α_k λ^k > 0` for all eigenvalues λ of W; heat, diffusion, cosine and p-step random-walk kernels are special cases. Features come from the deconvolution f of α (`Σ_{p=0}^k f_p f_{k−p} = α_k`), `Φ_G = Σ_k f_k W^k`, estimated with n terminating walks per node; each walk deposits `(product of traversed edge weights) × f_len / p(ω)` where p(ω) is the walk's sampling probability (importance weighting). For attention, the joint feature is `vec(φ(q_i) ⊗ φ_G(v_i))` of length mN (m = linear-attention feature dim), whose dot products equal `K_LR,ij · M_α,ij`; masked linear attention is `D^{-1}(Φ_Q(Φ_Kᵀ V))`, `D = Φ_Q(Φ_Kᵀ 1_N)`. Linear-attention maps mentioned: `elu(x)+1`-style linear transformer and Performer's Monte-Carlo softmax; ViT experiments used ReLU feature maps. — [arXiv HTML 2410.03462v2](https://arxiv.org/html/2410.03462v2)
- q-GRFs antithetic termination (NeurIPS 2023): each walker halts when its termination random variable (TRV) `t ~ Unif(0,1)` falls below p; the antithetic partner uses `t₂ = mod₁(t₁ + ½)`; marginals stay uniform (unbiased); for p ≤ ½ the two walkers can never halt on the same step; conditioned on one walk length m the partner's expected length is `(1−2p)/p + 2((1−2p)/(1−p))^m`. Corollary 3.3: up to ⌊1/p⌋ walkers can be mutually antithetic with offsets Δ = p; Theorem 3.4: offsets in [p(1−p), p] also reduce variance. — [arXiv HTML 2305.12470](https://arxiv.org/html/2305.12470)
- GRFs++ (2025): (i) **walk stitching** — multiply l independent pairs of short-walk feature matrices, `K_α(W) ≈ Π_{i=1..l} K1^(i) (K2^(i))ᵀ`; l=1 recovers GRFs; unbiasedness requires f to satisfy a 2l-fold convolution condition; for diffusion kernels `f(p) = 1/((2l)^p p!)`; general recipe = Taylor coefficients of the (2l)-th root of the kernel's generating function. (ii) **General walk-length distributions** (Alg. 2) — sample lengths `s_1..s_m ~ P` i.i.d., divide each load update by `τ(k)=P(X≥k)`, drop the per-step (1−p_halt) factor; geometric P recovers GRFs; a Poisson P with matched mean was tested. — [arXiv HTML 2510.07716v1](https://arxiv.org/html/2510.07716v1)

**Variance / concentration results and their dependence on degree, p_halt, diameter**
- Choromanski 2023, Thm A.2: `Var(M(i,j)) = (1/m²)(Λ − K²(i,j))` for i≠j, Λ a sum over quadruples of walks weighted by Γ; degree enters via `A(ω) = Π_s deg(v_s)/(1−p_term)`; no closed-form degree bound; "concentration beyond second-moment methods" explicitly left open; error curves were similar across p_term ∈ {0.1, 0.06, 0.01}. Error < 2 % at m = 80 on the tested graphs. — [ar5iv 2305.00156](https://ar5iv.labs.arxiv.org/html/2305.00156)
- q-GRFs Thm 3.2: for *any* graph, q-GRFs have lower variance than GRFs for `(I−U)^{-2}` (and the 2-regularised Laplacian kernel) if either p is sufficiently small or the spectral radius ρ(U) is sufficiently small. Quantitative: diffusion-simulation MSE GRF→q-GRF: larger ER (N=100) 0.0179→0.0085; ladder 0.0190→0.0105; karate 0.066→0.054 ("halved" in extreme cases); clustering error karate 0.11→0.05, citeseer 0.02→0.01, but eurosis got worse 0.15→0.19 (equal or better in 6 of 8 cases). Binary tree was one of the kernel-estimation graphs on which q-GRFs performed best (relative Frobenius error, Fig. 2; no table). — [arXiv HTML 2305.12470](https://arxiv.org/html/2305.12470)
- u-GRFs: no explicit variance bound; gives a Rademacher-complexity bound growing with spectral radius ρ(W); minimum walk-length batch needed to cover all m walks w.h.p. grows only logarithmically in m; qualitatively lower p_halt → longer walks → better approximation. — [arXiv HTML 2310.04859v3](https://arxiv.org/html/2310.04859v3)
- ICLR 2025 concentration theorem: with `c = Σ_k |f_k| (max_ij |W_ij| d_i /(1−p_halt))^k` finite (requires bounded f with suitably normalised W, or f vanishing beyond a max length), `Pr(|M̂−M| > t) ≤ 2 exp(−t² n³ / (2(2n−1)² c⁴))` — the first exponential concentration bound for GRFs; degree and edge weights enter only through c (larger degree weakens the bound); the bound does not depend on N for fixed c; unbounded c (unnormalised W, unbounded f) breaks the guarantee. A sparsity lemma bounds nonzeros per feature w.h.p. in terms of n, δ, p_halt. — [arXiv HTML 2410.03462v2](https://arxiv.org/html/2410.03462v2)
- GRFs++: exact MSE formula for l=2: `‖E[X₁²]‖²_F − ‖K_α(W)‖²_F`; Thm 3.3: under standard termination the MSE is non-increasing across stitching degrees 1, 2, 4, … ; expected nonzeros per feature for regular GRFs ≈ `N·m·(1−p_halt)/p_halt`. No bound in terms of diameter is given. — [arXiv HTML 2510.07716v1](https://arxiv.org/html/2510.07716v1)

**Behaviour on sparse / high-diameter graphs and trees (zero-estimate problem)**
- GRFs++ states the problem directly: in regular GRFs two nodes whose walks never intersect get an estimate of exactly zero; the probability of a walk reaching length r scales as `p_next^(r−2)`; stitching lets two nodes "communicate through a proxy node" with shorter walks, and with stitching degree ⌈r/2⌉ the probability is lower-bounded by an expression independent of p_next (expression not reproduced in the HTML). Long-distance experiments used Peptides graphs (434 nodes, **diameter 159**), CIFAR-10 superpixels (128), Reddit-Binary (436), Geometric Shapes (864). — [arXiv HTML 2510.07716v1](https://arxiv.org/html/2510.07716v1)
- ICLR 2025: "long-range interactions are sampled with lower probability", described as a design trade-off; accuracy improves monotonically with walker count n because the Monte-Carlo mask estimate becomes more accurate (Fig. 6, n ∈ {1,10,100,1000}, p_halt = 0.5, retrained from scratch; no numeric table). — [arXiv HTML 2410.03462v2](https://arxiv.org/html/2410.03462v2)
- Binary trees appear as test graphs in q-GRFs (kernel estimation) and GRFs++ (estimation) but neither paper reports a tree-specific analysis or numbers in the text I could access. — [q-GRFs HTML](https://arxiv.org/html/2305.12470); [GRFs++ HTML](https://arxiv.org/html/2510.07716v1)
- Choromanski 2023 notes the analysis assumes graphs with o(N²) edges and that for d>2 GRFs are mainly useful when K ≪ N (K = number of walk features kept); JLT compression costs O(N²K) (O(N² log K) structured). — [ar5iv 2305.00156](https://ar5iv.labs.arxiv.org/html/2305.00156)

**Mitigations and their costs (as reported)**
- Importance sampling (reweight by 1/p(ω) and edge-weight product): ICLR 2025 Table 3 ViT ImageNet test accuracy — GRF-masked 0.730; unmasked linear 0.693; "ad-hoc masked" (drops the 1/p(ω) and edge-weight factors, n=100, p_halt=0.5) 0.689; fully learnable graph features of same dimension 0.696. I.e. without importance sampling the mask is no better than no mask. — [arXiv HTML 2410.03462v2](https://arxiv.org/html/2410.03462v2)
- Antithetic termination (q-GRF): drop-in, no extra walks; valid for up to ⌊1/p⌋ coupled walkers; variance guarantee requires small p or small ρ(U). — [arXiv HTML 2305.12470](https://arxiv.org/html/2305.12470)
- Repelling random walks: QMC coupling of walker trajectories; drop-in; unbiased; used in ICLR 2025 point-cloud experiments ("3-hop repelling random walks", n = 3³ = 27 walks). — [arXiv 2310.04854](https://arxiv.org/abs/2310.04854); [arXiv HTML 2410.03462v2](https://arxiv.org/html/2410.03462v2)
- Walk stitching (GRFs++): costs l× more feature matrices; three compute options — (I) sparse K matrices, X,Y in O(N²); (II) JL projection `1/√r · K · G` with Gaussian G: O(N²) precompute, O(N) per X,Y for constant l,r; (III) right-to-left mat-vecs in O(N) for sparse matrices. Hyperparameters: l = 2 for classification/clustering/meshes; p_halt = 0.1 in most experiments (timing: base 0.01/0.001 scaled as p_halt × l); m = 256 (timing), 16 (clustering), {4,8,16} (normal prediction). Example gains: Football clustering error 0.0731 (GRF) → 0.0362 (GRF++, l=2); 5,985-vertex mesh normal cosine similarity GRF 0.9091, GRF++ 0.9154, exact 0.9194. — [arXiv HTML 2510.07716v1](https://arxiv.org/html/2510.07716v1)
- More walkers: variance ∝ 1/m² in the second-moment formula; n³/(2n−1)² ≈ n/4 in the exponent of the ICLR 2025 bound. — [ar5iv 2305.00156](https://ar5iv.labs.arxiv.org/html/2305.00156); [arXiv HTML 2410.03462v2](https://arxiv.org/html/2410.03462v2)

**Exact hyperparameters reported**
- Choromanski 2023: σ² = 0.2; p_term ∈ {0.1, 0.06, 0.01}; m ∈ {1,2,10,20,40,80}; graphs ER-0.4/ER-0.1 (N=1000), dolphins (62), eurosis (1272), Networking (1249), Databases (1046), Encryption-and-Compression (864), Hardware-and-Architecture (763); clustering with `p_term^{-1}·m ≤ 400`, K ≤ 0.6N. — [ar5iv 2305.00156](https://ar5iv.labs.arxiv.org/html/2305.00156)

Test accuracy ImageNet 0.730 (GRF) vs 0.693 (unmasked linear) vs 0.741 (softmax); iNaturalist2021 0.689/0.667/0.699; Places365 0.548/0.543/0.567. ViViT Kinetics-400: softmax 0.754 vs softmax+GRFs 0.758. The Kronecker/outer-product dimension is m·N where m is the linear-attention feature dimension (exact m for ViT not stated in the text I read). — [arXiv HTML 2410.03462v2](https://arxiv.org/html/2410.03462v2)

**Exact alternatives for small graphs**
- Exact kernel computation is "at least cubic in the number of nodes" (motivation for GRFs). — [arXiv 2305.00156](https://arxiv.org/abs/2305.00156)
- OpenGT measured preprocessing on PubMed (~19.7k nodes): random-walk statistics ≈ 10 min, spectral decomposition ≈ 1 h, all-pairs shortest paths up to 2 h; shortest paths O(n³) time dense / O(n³) space with path edge attributes; eigendecomposition O(n³) worst case. — [arXiv HTML 2506.04765v1](https://arxiv.org/html/2506.04765v1)
- GRIT states RRWP (truncated power series `(D^{-1}A)^k`, k < K) costs `O(K|V||E|)` to precompute and the full-attention model `O(|V|²)`. — [GRIT PDF](https://arxiv.org/pdf/2305.17589)
- GDT (NeurIPS 2025) computed RRWP at runtime because storing full random-walk matrices was too memory-intensive; on OGB-Code2 per-step runtime NoPE 0.092 s, LPE 0.104 s, SPE 0.105 s, RWSE 0.102 s, RRWP 0.219 s; memory ≈ 9.7–9.9 GB for NoPE/LPE/SPE/RWSE vs ≈ 19.2 GB for RRWP. — [arXiv HTML 2511.08028v1](https://arxiv.org/html/2511.08028v1)
- GRFs++ reports the "exact" diffusion-kernel baseline alongside GRF/GRF++ on a 5,985-vertex mesh (0.9194 vs 0.9154 vs 0.9091), i.e. exact is computed and still slightly better at ~6k nodes. — [arXiv HTML 2510.07716v1](https://arxiv.org/html/2510.07716v1)

### Inferences
- For ASTs with depth 10–50 and degree ≤ 10 at N = 1k–10k, a *truncated power series* `Σ_{k<K} α_k W^k` applied via K sparse mat-mults (cost O(K·nnz·d) for feature propagation, or O(K|V||E|) for the full pairwise matrix as GRIT states) is cheap enough that exact computation of the mask/kernel should be the default control; GRFs become attractive only when the pairwise N×N mask cannot be materialised (ICLR 2025 motivates them at >30k nodes). The GRFs++ mesh result (exact 0.9194 > GRF++ 0.9154 at ~6k vertices) supports "exact beats GRF when affordable".
- On trees the unique path between two nodes means walk intersection requires walks to traverse that exact path; with geometric lengths the chance of covering distance r is ∝ (1−p_halt)^r-type decay (the GRFs++ text frames this as `p_next^(r−2)`), so for AST depths 10–50 either p_halt must be ≤ 0.1 with ≥100 walkers (the ICLR 2025 from-scratch ViT setting) or stitching (l ≈ ⌈r/2⌉) must be used; otherwise many leaf–leaf pairs will have an exactly zero mask entry.
- Because the ICLR 2025 bound depends on `max_ij |W_ij| d_i`, the symmetric normalisation `w_ij = 1/√(d_i d_j)` is what keeps c finite on graphs with high-degree hubs; for ASTs with a few very wide nodes (argument lists) this normalisation should be kept.
- The ICLR 2025 ablation implies that the Monte-Carlo mask works because of exact importance weights; any "approximate" GRF implementation without 1/p(ω) reweighting is effectively a no-op versus unmasked linear attention.

- No paper in the lineage gives a variance bound explicitly as a function of graph **diameter**; only degree, p_halt, spectral radius and walker count appear. — [arXiv HTML 2510.07716v1](https://arxiv.org/html/2510.07716v1)
- No tree-specific GRF numbers (binary tree appears only as a plotted graph in q-GRFs/GRFs++ without tabulated values).
- Public code for the ICLR 2025 topological-masking paper and for GRFs++ was not found (both say "will be released"); the only author repos found are `general_graph_random_features`, `antithetic_termination`, `repelling_random_walks` under github.com/isaac-reid. A google-research GRF repo was not located in this search (unverified).
- The exact linear-attention feature dimension m used in the ViT experiments (and hence the Kronecker feature size mN) was not stated in the readable portion of the arXiv HTML.
- The ICML 2026 camera-ready of GRFs++ was not read (PMLR page only); concentration results mentioned in its conclusion were not visible in the arXiv v1 HTML.

## Key Question 2 — Theory of graph positional / structural encodings for a controlled study

### Takeaway
Black et al. (ICML 2024) prove APE-GTs and RPE-GTs are interchangeable in distinguishing power (with the caveat that converting RPE→APE can lose power on *featured* graphs), and that stacked powers of the normalised adjacency / Laplacian / heat kernels are at least as strong as the spectral kernel at no extra cost; GDT (NeurIPS 2025) empirically finds PE choice changes OGB-Code2 F1 by only ~0.2 while cost differs ~2× (RRWP). The best single default for a controlled tree + general-graph study is therefore a **random-walk power-series encoding** — RRWP as a relative encoding (K ≈ 21–32; O(K|V||E|) preprocessing, N×N×K memory) when pairwise bias is wanted, or RWSE (its diagonal) when only node features are affordable — because it is sign/basis-ambiguity-free, expresses SPD and heat/diffusion kernels, and is the same object the GRF mask estimates.

### Cited Findings

**Black et al. — APE vs RPE**

- *Graph Inductive Biases in Transformers without Message Passing* — Liheng Ma, Chen Lin, Derek Lim, Adriana Romero-Soriano, Puneet K. Dokania, Mark Coates, Philip Torr, Ser-Nam Lim, ICML 2023 (PMLR 202:23321–23337); arXiv:2305.17589; code https://github.com/LiamMa/GRIT. RRWP = stack of random-walk matrices `(D^{-1}A)^k`, k = 0..K−1 (Prop. 3.1 shows `MLP(P) ≈ Σ_k θ_k (D^{-1}A)^k`, and `MLP(P)_ij ≈ SPD_{K−1}(i,j)`); node input is `x_i = [x′_i ∥ P_ii] ∈ R^{d_h+K}` (diagonal = RWSE), pair input is P_ij; attention uses a signed-square-root `(ReLU(x))^{1/2} − (ReLU(−x))^{1/2}` to stabilise training and degree scalers; Prop. 3.2: GD-WL with RRWP distances is strictly stronger than GD-WL with SPD (distinguishes Dodecahedron vs Desargues); special cases of θ_k: mean aggregation, PPR `θ_k = α(1−α)^k`, K-truncated heat kernel `θ_k = e^{−τ} τ^k/k!`. Default K = 21 on ZINC; sensitivity Table 6 (MAE): K=2 0.147, 7 0.063, 14 0.063, 18 0.060, 21 0.059, 24 0.060, 42 0.061. Ablations on ZINC: RRWP→RWSE 0.081, RRWP→SPDPE 0.067, remove degree scaler 0.076, remove RRWP update 0.066 (full model ≈ 0.059). Complexity: RRWP precompute `O(K|V||E|)`, attention `O(|V|²)`; ZINC GPU memory SAN 2291 MB, GraphGPS 1101 MB, GRIT 1865 MB. — [GRIT PDF](https://arxiv.org/pdf/2305.17589); [arXiv abs](https://arxiv.org/abs/2305.17589)

**LapPE / RWSE / sign & basis ambiguity**
- *Recipe for a General, Powerful, Scalable Graph Transformer* (GraphGPS) — Ladislav Rampášek, Mikhail Galkin, Vijay Prakash Dwivedi, Anh Tuan Luu, Guy Wolf, Dominique Beaini, NeurIPS 2022; arXiv:2205.12454; classifies PEs/SEs as local / global / relative. — [arXiv abs](https://arxiv.org/abs/2205.12454) (RWSE-vs-LapPE recommendation not verified from abstract page — see Gaps)
- *Sign and Basis Invariant Networks for Spectral Graph Representation Learning* (SignNet / BasisNet) — Derek Lim, Joshua Robinson, Lingxiao Zhao, Tess Smidt, Suvrit Sra, Haggai Maron, Stefanie Jegelka; arXiv:2202.13013 (ICLR 2023 — venue unverified from page); invariant to sign flips and basis symmetries of eigenvectors; provably universal under conditions; subsume spectral graph convolutions and prior PEs. Code: https://github.com/cptq/SignNet-BasisNet — [arXiv abs](https://arxiv.org/abs/2202.13013)
- *On the Stability of Expressive Positional Encodings for Graphs* (SPE) — Yinan Huang, William Lu, Joshua Robinson, Yu Yang, Muhan Zhang, Stefanie Jegelka, Pan Li, ICLR 2024; arXiv:2310.02579; code https://github.com/Graph-COM/SPE. Formula: `SPE(V,λ) = ρ(V diag(φ₁(λ)) Vᵀ, …, V diag(φ_m(λ)) Vᵀ)` with d smallest eigenpairs, φ_l permutation-equivariant nets on eigenvalues, ρ a permutation-equivariant net (GIN in experiments) on the n×n×m tensor. Stability: if φ_l, ρ Lipschitz, output change ≤ (term ∝ √‖ΔL‖) + (linear term whose coefficient depends on the eigengap γ = λ_{d+1} − λ_d, vanishing as d→n). Expressivity: universal for continuous basis-invariant functions (Prop. 3.2); counts 3-,4-,5-cycles with 2-IGN ρ (Prop. 3.4). SignNet handles only sign invariance (unstable with repeated eigenvalues); BasisNet hard-partitions eigenspaces → discontinuous under perturbation; both worse OOD. ZINC MAE: SPE full 0.0693, SPE 8 eigvecs 0.0736, SignNet 0.0853, BasisNet 0.1555, no PE 0.1772; Alchemy SPE 0.108 vs no-PE 0.112; DrugOOD Assay AUROC 72.53 (best). Hyperparameters: d = 8 or full; m = 8 channels; φ_l ∈ {DeepSets, elementwise MLP, piecewise cubic splines (1–6 pieces)}; weight normalisation for Lipschitz control. Preprocessing cost not analysed in the main text (runtime in App. B.6, not read). — [arXiv HTML v3](https://arxiv.org/html/2310.02579v3); [arXiv abs](https://arxiv.org/abs/2310.02579)
- *Graph Positional and Structural Encoder* (GPSE) — Semih Cantürk, Renming Liu, Olivier Lapointe-Gagné, Vincent Létourneau, Guy Wolf, Dominique Beaini, Ladislav Rampášek, ICML 2024; arXiv:2307.07107; learns a shared latent encoding of multiple PSEs with a pre-trained encoder that transfers across datasets/modalities; integrated into PyG; code https://github.com/G-Taxonomy-Workgroup/GPSE. — [arXiv abs](https://arxiv.org/abs/2307.07107)

**Tree positional encodings for code**
- *Novel positional encodings to enable tree-based transformers* — Vighnesh Shiv, Chris Quirk, NeurIPS 2019. Desired property: for every tree path φ there is an affine transform in positional space; step-down to child i = affine operator D_i (concatenate one-hot n-vector e_i on the left, truncate on the right), step-up = U; hyperparameters n (tree degree, assumed regular) and k (max depth for which the constraint holds); encoding dimension n·k; root = zero vector; chunks may be weighted by any geometric series (decay p, e.g. 0.9 vs 0.7 illustrated; too much decay loses uniqueness). Trees are converted to left-child-right-sibling binary form; k = 32 in all experiments; "+22 % absolute" on JS→CoffeeScript (abstract reads "2%" in some renderings; the NeurIPS abstract page says 22 %). Limitation stated: expects regular trees. — [NeurIPS PDF](https://proceedings.nips.cc/paper_files/paper/2019/file/6e0917469214d8fbd8c517dcdc6b8dcf-Paper.pdf); [NeurIPS abstract](https://proceedings.neurips.cc/paper/2019/hash/6e0917469214d8fbd8c517dcdc6b8dcf-Abstract.html)
- Code Transformer distance encodings — see KQ3 (shortest path, ancestor, sibling, PPR; 32 bins). — [Code Transformer PDF](https://arxiv.org/pdf/2103.11318)
- TPTrans path encodings — see KQ3 (bi-GRU over nonterminal path, max path length 32). — [TPTrans NeurIPS PDF](https://papers.nips.cc/paper_files/paper/2021/file/4e0223a87610176ef0d24ef6d2dcde3a-Paper.pdf)

**Expressivity vs cost evidence (2025)**
- *OpenGT: A Comprehensive Benchmark For Graph Transformers* — Zhejiang Univ. (eaglelab-zju), arXiv:2506.04765 (June 2025); code https://github.com/eaglelab-zju/OpenGT. PEs compared: Graphormer bias (GE, GESP), WLSE, RWSE (spatial); LapPE, ESLapPE (spectral) on DIFFormer/GraphGPS/SGFormer. GE helps most on dense graphs (Chameleon +0.059/+0.070/+0.037; Squirrel +0.079/+0.071/+0.080) and is neutral/negative on Cora etc.; "utility of other positional encodings varies depending on the specific dataset and model architecture"; no default is recommended; PubMed preprocessing: RW stats ≈ 10 min, spectral ≈ 1 h, APSP ≈ 2 h. — [arXiv HTML](https://arxiv.org/html/2506.04765v1); [arXiv abs](https://arxiv.org/abs/2506.04765)
- *Generalizable Insights for Graph Transformers in Theory and Practice* (GDT) — Stoll, Müller, Morris, NeurIPS 2025 spotlight; arXiv:2511.08028. PEs: RWSE, RRWP, LPE, SPE, NoPE (RD and SPD "can be approximated by RWSE or RRWP"); APEs added to node embeddings `X_i = ℓ_V(i) + P_i W_P`, RPEs added to attention bias `B_ij = ρ(ℓ_E(i,j)) + U_ij W_U`. Theory: GDT simulates GD-WL (Thm 1), NoPE ≡ 1-WL; each PE strictly increases expressivity beyond 1-WL (Insight 2); SPE ≥ LPE and ≥ RRWP, LPE ≥ RWSE (Prop. 4). OGB-Code2 (AST-derived graphs, 16M params) test F1: NoPE 19.27, LPE 19.48, SPE 19.35, RWSE 19.39, RRWP 19.42 (spread ≈ 0.2); Insight 3: "PE efficiency can vary greatly while predictive performance differences are less pronounced". PE hyperparameters: 32 RW steps / 32 eigenvectors for Code; hidden 768 (RWSE/RRWP) vs 384 (LPE/SPE); φ, ρ 2 layers; SPE ρ = GIN; RRWP computed at runtime (storage too large), 2× L40 GPUs. Runtime/memory per step on Code: see KQ1. — [arXiv HTML](https://arxiv.org/html/2511.08028v1); [NeurIPS page](https://neurips.cc/virtual/2025/poster/118030)

### Inferences
- For a *controlled* study that must run on both ASTs (trees) and general graphs with one encoding, RRWP/RWSE (random-walk power series) is the most defensible default: (a) no sign/basis ambiguity (unlike LapPE; SPE fixes this at the price of an eigendecomposition plus a GIN on an n×n×m tensor); (b) Black et al. show stacked powers of Â are at least as strong as the spectral kernel; (c) GRIT shows RRWP ⊋ SPD under GD-WL and that PPR/heat kernels are special cases, so the same encoding covers Code Transformer's PPR/SPD distances; (d) GDT shows on AST graphs (OGB-Code2) that PE choice barely moves F1, so the cheaper RW family loses nothing measurable; (e) it is exactly the object `Σ_k θ_k W^k` that the GRF mask estimates, making an exact-vs-GRF ablation clean.
- Preprocessing cost at N = 1k–10k for RRWP with K = 21–32: K sparse mat-mults, O(K|V||E|) ≈ 32 × 10k × ~10k (tree: |E| ≈ N) ≈ 3×10⁹ scalar ops worst case (seconds on GPU), but materialising N×N×K pair features at N = 10k, K = 32 is 3.2×10⁹ floats (≈ 12.8 GB fp32) — hence GDT's "compute at runtime" and 2× memory. RWSE (diagonal only) is N×K and negligible. LapPE/SPE need an eigendecomposition: O(N³) dense (~minutes for N = 10k per OpenGT's hour-scale on 19.7k PubMed) or partial Lanczos for d = 8–32 eigenpairs.
- Black et al.'s warning (RPE→APE loses power with node features) argues for keeping the structural signal as an **attention bias / mask (RPE)** in a token–graph fusion model, rather than only adding node PEs to token embeddings.

### Gaps
- GraphGPS's practical rule "RWSE for molecules, LapPE elsewhere" and SignNet usage could not be verified from the abstract page fetched (full text not read) — treat as unverified.
- SPE preprocessing runtime (App. B.6) and Black et al.'s code URL were not in the portions read.
- No paper evaluated these PEs on ASTs *as trees* with depth 10–50 except indirectly via OGB-Code2 in GDT; Shiv & Quirk's encoding has not, to my knowledge from this search, been compared head-to-head with RRWP/LapPE.

## Key Question 3 — Token-to-node alignment and structure-guided attention in NLP and code

### Takeaway
Prior code models align tokens and AST nodes in one of three ways: (i) GraphCodeBERT appends graph nodes as extra tokens and uses a hard 0/−∞ mask that lets a node attend only to the subword span it was "identified from" and to its data-flow predecessors; (ii) Code Transformer / GREAT / TPTrans keep *only tokens* (leaves) as the sequence and push structure into pairwise relative encodings (smallest-enclosing-AST-node assignment, 32-bin distances, edge-type biases, GRU-encoded leaf-to-leaf paths); (iii) NLP work (Sachan et al.) expands word-level dependency edges to wordpieces by linking the head subword to tail subwords and sums wordpiece states back to words. Negative evidence: Sachan et al. gain >2.5 F1 only with gold parses and lose it with Stanza parses; GDT finds PE choice on AST graphs moves F1 by ~0.2. On subword pooling, Ács et al. (EACL 2021) find "first subword" is the *worst* choice for morphology and that attention/LSTM pooling over subwords is best; GREAT and Code Transformer use mean / fixed-5-slot subtoken embeddings.

### Cited Findings

**GraphCodeBERT (Guo et al., ICLR 2021; arXiv:2009.08366; code https://github.com/microsoft/CodeBERT)**
- Graph-guided masked attention: `M_ij = 0 if q_i ∈ {[CLS],[SEP]} or q_i,k_j ∈ W ∪ C or ⟨q_i,k_j⟩ ∈ E ∪ E′; −∞ otherwise`, where E are data-flow edges (node-query v_i may attend node-key v_j iff ⟨v_j, v_i⟩ ∈ E or i=j) and E′ contains ⟨v_i, c_j⟩/⟨c_j, v_i⟩ iff variable v_i "is identified from" source token c_j. Variables get a special shared position embedding to mark them as nodes. Pre-training: MLM + Edge Prediction (mask 20 % of nodes' edges, predict) + Node Alignment (mask 20 % of nodes' node–token edges, predict which token the variable is identified from). Removing NodeAlign/EdgePred drops code-search MRR from 0.713 to ~0.703–0.707. Pre-training lengths: sequence 512, nodes 128; fine-tuning: code 256, nodes 64, query 128. — [GraphCodeBERT PDF](https://arxiv.org/pdf/2009.08366)
- Implementation (`codesearch/run.py`): `extract_dataflow` strips comments (`remove_comments_and_docstrings`; on failure keeps raw code), wraps PHP in `<?php ... ?>`, parses with tree-sitter, `tree_to_token_index` gives leaf spans, `index_to_code_token` gives token text, `DFG_<lang>` builds edges; on failure DFG = []. Subword step: each raw token after the first is tokenized as `'@ ' + x` with the leading `@` piece dropped to keep the BPE word-boundary marker; `ori2cur_pos` maps raw-token index → (start,end) subword span; `dfg_to_code` stores each node's subword span (+1 for CLS) — this is the node-to-token alignment; `dfg_to_dfg` stores neighbour node indices (truncated neighbours dropped); DFG nodes are appended after code tokens with `position_idx = 0` and id = unk. Mask in `TextDataset.__getitem__`: boolean (code_length + data_flow_length)²; real code tokens attend each other fully; CLS/SEP attend all non-pad; for each node, row and column over its subword span set True (both directions); node-to-node set only along `dfg_to_dfg` (one-directional as written). Pitfalls: bare `except` clauses silently yield examples with no data-flow; `code_tokens` may be unbound if parsing fails before assignment. Defaults: code_length 256, data_flow_length 64, nl_length 128. — [run.py](https://raw.githubusercontent.com/microsoft/CodeBERT/master/GraphCodeBERT/codesearch/run.py)

**Code Transformer (Zügner, Kirschstein, Catasta, Leskovec, Günnemann, ICLR 2021; arXiv:2103.11318)**
- Alignment: "we assign each token in the sequence to an AST node by selecting the AST node whose range in the source code is the shortest one containing the token"; token embedding is concatenated with the assigned AST node-type embedding and tokenizer token-type; "among all the internal nodes, we use as input only those corresponding to a token in the sequence; however, the remaining internal nodes can [be] used by the model since their presence affects the distances". Appendix A.3.2: greedy descent choosing the child with shorter source range when several children's ranges contain the token, because the non-overlap assumption "does not hold for all ASTs"; snippets with AST parse errors are discarded. — [Code Transformer PDF](https://arxiv.org/pdf/2103.11318)
- Distances: shortest-path length on the *undirected* AST (otherwise leaves cannot reach anything), ancestor shortest paths (bidirectional, parent→child = +1, child→parent = −1, non-ancestors get a very large value), next-sibling shortest paths, personalized PageRank (−log PPR as distance). Encoded XLNet-style as relative position encodings φ(r_{i→j}) with learnable bias vectors u, v; continuous distances grouped into k = 32 bins (model "relatively insensitive" to k). Ablation on Java-small (structure-only, no pointer) F1: sibling 46.17, ancestor 47.89, shortest path 47.76, PPR 48.47; all four combined is better. — [Code Transformer PDF](https://arxiv.org/pdf/2103.11318)
- Subtokens: each token split by naming convention into subtokens; **5 input subtokens per token**, padded with [PAD]; method names up to 6 subtokens; strings/numbers masked; Pygments tokenizer; ASTs from java-parser (Java) and GitHub `semantic` (Python/JS/Ruby/Go). — [Code Transformer PDF](https://arxiv.org/pdf/2103.11318)

**GREAT (Hellendoorn, Maniatis, Singh, Sutton, Bieber, ICLR 2020; code https://github.com/VHellendoorn/ICLR20-Great; data DOI 10.5281/zenodo.3668323)**
- Relational attention: a learned projection of the edge-type embedding for pair (i,j) is added to the attention logit (query term; biases summed when several edge types connect a pair). Edge types borrow from Allamanis et al. 2018 (data-flow read/write edges, adjacent-token edges, syntactic edges) plus control-flow-statement and function-call edges. "Leaves-only" representation (default for GREAT/sandwich): AST removed, edges from internal nodes moved down to the leaf node of each span's *begin token*, ≈ 2–3× fewer nodes. Subtokens: Tensor2Tensor subword encoder, 10K vocab, each token embedding = **average of its subtoken embeddings** (128-d). — [GREAT text](https://object.cloud.sdsc.edu/v1/AUTH_da4962d3368042ac8337e2dfdd3e7bf3/ml-papers-txt/ICLR/2020/global_relational_models_of_source_code__ae1fb05d.txt); [ICLR page](https://iclr.cc/virtual/2020/poster/1945)

**TPTrans (Peng, Li, et al., NeurIPS 2021; code https://github.com/AwdHanPeng/TPTrans)**
- Tokens are AST terminals (leaves) from Tree-Sitter; relative path = nonterminal sequence between two terminals encoded by a bi-GRU, `r_ij = GRU_r(Path_{x_i→x_j})`, used as key/value bias in attention; absolute path = terminal-to-root nonterminal sequence, `a_i = GRU_a(Path_{x_i→root})`, projected with W_aQ, W_aK. Subtokens split by naming convention (as in Alon et al., Zügner et al.); nonterminal literals not split; **max path length 32**; max distinct relative paths l = 512, absolute 256 per sample (dedup since many pairwise paths repeat); one-layer Bi-GRU hidden 64 with layer-norm GRU for stability; datasets CodeSearchNet Python/JS/Go/Ruby method naming. — [TPTrans NeurIPS PDF](https://papers.nips.cc/paper_files/paper/2021/file/4e0223a87610176ef0d24ef6d2dcde3a-Paper.pdf)

**AST-Trans (Tang et al., ICSE 2022; code https://github.com/zetang94/ICSE2022_AST_Trans)**
- Linearises the AST and replaces self-attention with tree-structured attention over two relation matrices: ancestor–descendant (shortest-path distance along root paths) and sibling (horizontal distance), with ∞ where the relation does not hold, used to exclude irrelevant nodes; motivation: ASTs are much longer than source. — [ICSE 2022 record](https://conf.researchr.org/details/icse-2022/icse-2022-papers/160/AST-Trans-Code-Summarization-with-Efficient-Tree-Structured-Attention); [arXiv preprint (AST-Transformer)](https://arxiv.org/pdf/2112.01184)

**NLP: dependency / syntax-guided attention**
- *Do Syntax Trees Help Pre-trained Transformers Extract Information?* — Devendra Singh Sachan, Yuhao Zhang, Peng Qi, William Hamilton, EACL 2021; arXiv:2008.09084; code on GitHub (URL in paper). Subword mapping (§2.2.1 "Dependency Tree over Wordpieces"): the dependency tree is extended to wordpieces by adding edges from the first subword (head word) of a token to the remaining subwords (tail words) of the same token; outputs are mapped back "by adding the hidden states of all the wordpieces that map to the same linguistic token". Late Fusion: syntax-GNN (graph conv + attention aggregation) stacked over BERT with a Highway gate `g_i = σ(W_g v_i + b_g)`, `h_i = g_i ⊙ v_i + (1−g_i) ⊙ z_i`. Joint Fusion: syntax-GNN hidden states linearly projected by P_K, P_V into extra keys/values that are *added to* BERT's self-attention keys/values in every layer (two new weight sets per layer). Results: with gold parses Joint Fusion +3.5 F1 (CoNLL-2005 SRL) and Late Fusion +2.65 over bert-base; RE Late Fusion improves but Joint Fusion drops 4.5 F1; NER no significant gain even with gold trees. With Stanza predicted parses (UAS 84.20 / 82.73) the SRL gains largely vanish (e.g. 87.45/87.36 F1 vs ≈ 90 with gold); "performance gains are highly contingent on the availability of human-annotated dependency parses". — [arXiv PDF](https://arxiv.org/pdf/2008.09084); [arXiv abs](https://arxiv.org/abs/2008.09084)
- *Syntax-BERT: Improving Pre-trained Transformers with Syntax Trees* — Jiangang Bai, Yujing Wang, Yiren Chen, Yaming Yang, Jing Bai, Jing Yu, Yunhai Tong, EACL 2021; arXiv:2103.04350; plug-and-play syntax-tree masks applicable to any Transformer checkpoint; consistent gains over BERT/RoBERTa/T5 on NLU. (Mask details — parent/child/sibling/distance masks and topical pooling — **unverified**, abstract only.) — [arXiv abs](https://arxiv.org/abs/2103.04350)
- *Tree Transformer: Integrating Tree Structures into Self-Attention* — Yau-Shian Wang, Hung-Yi Lee, Yun-Nung Chen, EMNLP 2019; arXiv:1909.06639; "Constituent Attention" implemented as self-attention between adjacent words, constraining heads to follow induced tree structure; better LM perplexity under BERT-style training. — [arXiv abs](https://arxiv.org/abs/1909.06639)
- *SG-Net: Syntax-Guided Machine Reading Comprehension* — Zhuosheng Zhang, Yuwei Wu, Junru Zhou, Sufeng Duan, Hai Zhao, Rui Wang, AAAI 2020; arXiv:1908.05147; syntactic-dependency-of-interest (SDOI) mask inside a self-attention network, combined with the vanilla SAN in a dual-context architecture; gains on SQuAD 2.0 and RACE. — [arXiv abs](https://arxiv.org/abs/1908.05147)

**Span pooling of subword states into node states — evidence**
- *Subword Pooling Makes a Difference* — Judit Ács, Ákos Kádár, András Kornai, EACL 2021 (2021.eacl-main.194); arXiv:2102.10864; code https://github.com/juditacs/subword-choice. Nine languages, mBERT and XLM-R, tasks morphology / POS / NER: "first subword" is the **worst** strategy for morphology; attention over subwords is best for morphology; a small LSTM over subwords is best for POS and NER; the paper reports the first-vs-last gap matters (first is generally worse than last for morphology/POS but best for NER). Mean/max numbers are in the repo's result tables (not read). — [arXiv abs](https://arxiv.org/abs/2102.10864); [ACL Anthology](https://preview.aclanthology.org/dois-2013-emnlp/2021.eacl-main.194)
- Practices in code models: GREAT averages subtoken embeddings; Code Transformer uses a fixed 5-slot subtoken input per token; GraphCodeBERT gives a node a *span* (all subwords) via the mask rather than pooling; Sachan et al. sum wordpiece states per word and link head→tail subwords in the graph. — [GREAT text](https://object.cloud.sdsc.edu/v1/AUTH_da4962d3368042ac8337e2dfdd3e7bf3/ml-papers-txt/ICLR/2020/global_relational_models_of_source_code__ae1fb05d.txt); [Code Transformer PDF](https://arxiv.org/pdf/2103.11318); [run.py](https://raw.githubusercontent.com/microsoft/CodeBERT/master/GraphCodeBERT/codesearch/run.py); [Sachan PDF](https://arxiv.org/pdf/2008.09084)

### Inferences
- The smallest-enclosing-range rule (Code Transformer) and the begin-token rule (GREAT leaves-only) are the two reusable recipes for mapping *internal* AST nodes to tokens; GraphCodeBERT's `tree_to_token_index` + `ori2cur_pos` recipe is the reusable one for mapping *leaf* nodes to subword spans. For a token-sequence + graph fusion model, the simplest robust design is: leaf node ↔ subword span (mask over span, as GraphCodeBERT), internal node ↔ union of descendant leaf spans (or the begin token, as GREAT).
- Evidence on pooling is from NLP tagging tasks, not code; still, it suggests **not** using first-subword pooling for node states and preferring attention-pooling (or at least mean) over the span. A no-pooling alternative with equal evidence in code is to give the node its own token whose attention is masked to its span (GraphCodeBERT), which lets the model learn the pooling.
- Sachan et al.'s result is the strongest negative finding: structure injected into attention helps only when the structure is accurate; for code, parser output (tree-sitter) is near-gold, so the failure mode shifts to *incomplete/ERROR parses* (see tooling section) rather than noisy parses.

### Gaps
- Syntax-BERT's exact mask families and SG-Net's exact SDOI mask formula were not verified (abstract pages only).
- No study was found that directly measures information loss of first/mean/attention pooling for **code tokens → AST nodes**; the Ács et al. evidence is for natural-language morphology/POS/NER.
- Sachan et al.'s GitHub URL was truncated in the extracted text ("https://github.com/" followed by a line break); not reproduced here.

## Appendix — Tree-sitter-based AST + def-use extraction tooling and pitfalls

### Takeaway
The de-facto reference implementation is GraphCodeBERT's `parser/` package (seven `DFG_<lang>` functions over tree-sitter, `comesFrom`/`computedFrom` edges, two-pass loop heuristic); it has known silent-failure paths, and tree-sitter's C/C++ grammars parse *post-preprocessed* code, so macros/`#if` branches produce ERROR nodes and misparses that must be checked (`root_node.has_error()`).

### Cited Findings
- GraphCodeBERT parser directory files: `DFG.py`, `__init__.py`, `build.py`, `build.sh`, `my-languages.so`, `utils.py`. — [GitHub tree](https://github.com/microsoft/CodeBERT/tree/master/GraphCodeBERT/codesearch/parser)
- `DFG.py` defines `DFG_python`, `DFG_java`, `DFG_csharp`, `DFG_ruby`, `DFG_go`, `DFG_php`, `DFG_javascript`; each takes (node, index_to_code, states) and returns edges `(name, index, label, source_names, source_indices)` with labels `comesFrom` (use/simple binding) and `computedFrom` (assignment from several sources). Python handling: `default_parameter`; `assignment`/`augmented_assignment`/`for_in_clause` (element-wise split when LHS/RHS lengths match); `if_statement` branches on copies of `states` merged by union; `for_statement`/`while_statement` bodies processed **twice** as a loop-carried-dependency approximation; everything else recursed. Limitations: no special handling of function/class defs, calls, decorators, attribute access; branch merge ignores path conditions; tuple-order inconsistency between def and assignment edges; a dead `'else' in root_node.type` check. — [DFG.py](https://raw.githubusercontent.com/microsoft/CodeBERT/master/GraphCodeBERT/codesearch/parser/DFG.py)
- Pipeline and failure handling in `run.py` (bare `except` → empty DFG; possible unbound `code_tokens`): see KQ3. — [run.py](https://raw.githubusercontent.com/microsoft/CodeBERT/master/GraphCodeBERT/codesearch/run.py)
- GraphCodeBERT paper cites tree-sitter (https://github.com/tree-sitter/tree-sitter) as the compiler tool used to build data flow; all code/data at https://github.com/microsoft/CodeBERT. — [GraphCodeBERT PDF](https://arxiv.org/pdf/2009.08366)
- TPTrans parses CodeSearchNet with Tree-Sitter (https://github.com/tree-sitter/); Code Transformer uses java-parser and GitHub `semantic` (https://github.com/github/semantic) and discards snippets with parse errors. — [TPTrans PDF](https://papers.nips.cc/paper_files/paper/2021/file/4e0223a87610176ef0d24ef6d2dcde3a-Paper.pdf); [Code Transformer PDF](https://arxiv.org/pdf/2103.11318)
- C/C++ pitfalls: the tree-sitter-c author's stated position (quoted in an Emacs bug thread) is that the grammar targets post-preprocessed C and leaves macros to error recovery; skipped tokens land in ERROR nodes. — [bug-gnu-emacs thread](https://lists.nongnu.org/archive/html/bug-gnu-emacs/2022-11/msg01966.html). Preprocessor directives (`#if`, `#include`) can appear mid-rule and change it; `#if/#else` branches produce ERROR nodes mid-declaration. — [habr analysis](https://habr.com/en/articles/835192). Macros in a class declaration cause the class to be misparsed as a function definition. — [tree-sitter-cpp issue #293](https://github.com/tree-sitter/tree-sitter-cpp/issues/293). Qt-style macro-heavy files yield garbage trees with spurious nodes. — [emacs-devel thread](https://yhetil.org/emacs-devel/CAOpc7mGa-kFtm7Y7GzGmOGVdPb1PAEnjPHD5yMTsRgGS0x0wmQ@mail.gmail.com)

### Inferences
- A production AST+DFG pipeline should: (1) check `root_node.has_error()` and count ERROR/MISSING nodes, dropping or flagging samples above a threshold (Code Transformer simply discards parse-error snippets); (2) for C/C++, strip or stub known macros before parsing, or parse per-`#if` branch; (3) replace GraphCodeBERT's bare `except` with logged failures so the fraction of graph-less samples is known; (4) note that the two-pass loop heuristic under-approximates loop-carried def-use for nested loops.

### Gaps
- CodeXGLUE-specific parser scripts and a `python_parser` module were not separately verified in this search; the GraphCodeBERT `parser/` package is the verified artefact (CodeXGLUE tasks reuse it — unverified).
- No peer-reviewed study quantifying tree-sitter ERROR-node rates on C/C++ corpora was found; evidence is from issue trackers and mailing lists.
