# LLM + Graph-Structure Integration (2022–2026): Deep-Injection Methods, Efficiency Claims, and Head-to-Head Comparisons

Scope note: catalogue built 2026-11-02 from arXiv full texts (HTML), arXiv abstract pages, ACL Anthology/OpenReview metadata, the Semantic Scholar citation graph of GraphToken (160 citing papers returned; the LLaGA / Plenz&Frank / ENGINE / GraphAdapter citation queries were rate-limited, see Gaps), and the two main awesome-lists. Where a fetched page did not confirm a detail it is marked **[unverified]**. Numbers are copied as reported by the papers; "pp" = percentage points.

Legend for the injection-point field used throughout:
- **INPUT-SOFT** = graph encoder output projected to soft tokens / prefix at the input embedding layer only
- **PREFIX-KV** = learned prefix prepended to keys/values at every attention layer (prefix-tuning style)
- **XATTN** = cross-attention adapter (Q-Former / Translator) between graph encoder and LLM
- **SIDE** = per-layer side branch (ladder / adapter / interleaved GNN) reading LLM hidden states
- **ATTN-BIAS** = additive term on attention logits derived from graph distance / structure
- **ATTN-MASK** = graph-derived attention mask (sparsified attention)
- **POS** = positional-encoding modification (relative PE on graph distance, RoPE reset / shared position id)
- **WEIGHT** = graph-conditioned weight update (generated LoRA)
- **OUTPUT** = fusion only at final hidden state / logits
- **TEXT** = structure serialized as text, no architectural change

## Key Question 1: Verified details of the named foundation methods (GraphToken, GraphLLM, LLaGA, GraphGPT, G-Retriever, ENGINE, GraphAdapter, Graph Language Models, GreaseLM, QA-GNN, DRAGON, GLEM, TAPE, Patton, SimTeG, InstructGLM, GraphTranslator, HiGPT, GOFA, GraphText, TEA-GLM, GNP, GraphPrompter, MolCA)

### Takeaway
Almost all 2023–2024 "graph-to-LLM" methods inject structure only at the input (INPUT-SOFT) into a *frozen* ~7B decoder (Vicuna-7B / Llama-2-7B / PaLM-2-S), training only a GNN + projector; the exceptions that go deeper are GraphLLM (PREFIX-KV at every layer), ENGINE (per-layer SIDE ladder), GOFA (GNN layers interleaved between the last LLM layers), GraphAdapter (OUTPUT-level fusion), Plenz & Frank's GLM (relative-PE + mask inside a T5 encoder), and the 2021–2022 encoder-LM lineage (QA-GNN, GreaseLM, DRAGON, Patton) that fused GNNs into RoBERTa/BERT layers. Efficiency claims are mostly about trainable parameters (0.1M–130M vs. 7B) and, for ENGINE / GraphLLM / G-Retriever, about training time and context tokens.

### Cited Findings

**INPUT-SOFT (soft tokens / prefix at the input only)**

- **GraphToken — "Let Your Graph Do the Talking: Encoding Structured Data for LLMs"** (Perozzi, Fatemi, Zelle, Tsitsulin, Kazemi, Al-Rfou, Halcrow; arXiv Feb 2024, no peer-reviewed venue listed). LLM: PaLM 2 S (Flan instruction-tuned checkpoint), **frozen**; only the graph encoder is trained. Encoders tried: GCN, GIN, MPNN, HGT, Multi-Head-Attention graph transformer, plus linear "Node Set"/"Edge Set"; no single encoder dominates. Output: a fixed number of token embeddings prepended to the embedded text prompt. Benchmark: GraphQA (node count, edge count, cycle check, triangle counting, node degree, connected nodes, reachability, edge existence, shortest path). Baselines: zero-shot, zero-CoT, few-shot, CoT, CoT-BAG, soft-prompt tuning. Trainable params: encoder body ~17k–199k (page also cites a ~11M projection head and ~80k prompt embedding — figures inconsistent in the extraction). GraphQA test accuracies: node count 0.996, edge count 0.426, cycle check 0.956, triangle counting 0.348, node degree 0.962, connected nodes 0.264, reachability 0.932, edge existence 0.738, shortest path 0.638; the soft-prompt baseline beats GraphToken on cycle check (0.832) via majority-label guessing. Headline "up to 73 pp" improvement. — [arXiv abs](https://arxiv.org/abs/2402.05862); [arXiv HTML](https://arxiv.org/html/2402.05862v1)
- **LLaGA — "LLaGA: Large Language and Graph Assistant"** (Chen, Zhao, Jaiswal, Shah, Wang; arXiv Feb 2024; ICML 2024 **[venue unverified on arXiv page]**). LLM: Vicuna-7B-v1.5-16K (**frozen**; Appendix also tests LLaMA2-7B and OPT-2.7B). Only an MLP projector is trained ("the only parameters subject to tuning"). No GNN: two templates — *Neighborhood Detail* (fixed-shape 2-hop computational tree, 10 sampled neighbors/hop, level-order flattened node sequence with Laplacian positional embeddings) and *Hop-Field Overview* (4 hop embeddings by parameter-free mean message passing). Text encoder: SimTeG default (SBERT / RoBERTa in appendix). Datasets: ogbn-arxiv, ogbn-products, PubMed, Cora; tasks: node classification, link prediction, node description. Baselines: GCN, GraphSAGE, GAT, SGC, SAGN, NodeFormer, GPT-3.5-Turbo, GraphGPT. Key numbers (single-focus LLaGA-HO-7B): node cls Arxiv 76.66 / Products 84.67 / PubMed 95.03 / Cora 89.22; link pred Arxiv 94.15 / Products 95.56 / PubMed 89.18 / Cora 86.82. Training: one epoch, lr 2e-5; no training time / projector param count reported. — [arXiv abs](https://arxiv.org/abs/2402.08170); [arXiv HTML](https://arxiv.org/html/2402.08170v3)
- **GraphGPT — "GraphGPT: Graph Instruction Tuning for Large Language Models"** (Tang, Yang, Wei, Shi, Su, Cheng, Yin, Huang; SIGIR 2024). LLM: Vicuna-7B-v1.1 / v1.5, **frozen** in both tuning stages; graph transformer encoder (pretrained with text-graph grounding) also frozen; only a projector ("can be as simple as a single linear layer") is trained. Datasets: ogbn-arxiv, PubMed, Cora (70-class). Baselines: MLP, GraphSAGE, GCN, GAT, RevGNN, DGI, GKD, GLNN, NodeFormer, DIFFormer, Baichuan-7B, Vicuna-7B. Results: supervised Arxiv 0.7511 (GraphGPT-7B-v1.5-stage2) vs 0.6088 best baseline GLNN; zero-shot Arxiv→PubMed 0.7011 vs Vicuna-7B-v1.5 0.6351; Arxiv→Cora(70-way) 0.1813 vs 0.1489. Cost: ~131.6M trainable params in frozen setting vs ~6.6B if the LLM is tuned (which OOMed at batch 1 on 4×A100-40GB); Stage-1 ≈22.9 h, Stage-2 ≈3.7 h. — [arXiv abs](https://arxiv.org/abs/2310.13023); [arXiv HTML](https://arxiv.org/html/2310.13023v3)
- **G-Retriever — "G-Retriever: Retrieval-Augmented Generation for Textual Graph Understanding and Question Answering"** (He, Tian, Sun, Chawla, Laurent, LeCun, Bresson, Hooi; arXiv Feb 2024; NeurIPS 2024 **[venue unverified on arXiv page]**). LLM: Llama2-7B frozen (variant with LoRA). Encoder: Graph Transformer (4 layers, 4 heads, hidden 1024); mean-pool + MLP → **one** graph token prepended as soft prompt; retrieval = top-k cosine + Prize-Collecting Steiner Tree. GraphQA benchmark: ExplaGraphs (2,766 graphs), SceneGraphs (100k), WebQSP (4,737 Qs, Hit@1). Baselines include zero-shot, zero-CoT, CoT-BAG, KAPING, prompt tuning, GraphToken, LoRA on textualized graph. Table: Prompt tuning 0.5763 / 0.6341 / 48.34; GraphToken 0.8508 / 0.4903 / 57.05; **G-Retriever 0.8516 / 0.8131 / 70.49**; LoRA (text only) 0.8538 / 0.7862 / 66.03; G-Retriever+LoRA 0.8705 / 0.8683 / 73.79. Efficiency: retrieval cuts WebQSP tokens 100,627 → 610 (−99 %), training 18.7 → 6.2 min/epoch; SceneGraphs tokens 1,396 → 235 (−83 %). Ablation (WebQSP): no graph encoder 54.62 (−22.5 %), no textualized graph 56.96 (−19.2 %), no retrieval 63.84. — [arXiv abs](https://arxiv.org/abs/2402.07630); [arXiv HTML](https://arxiv.org/html/2402.07630v3)
- **TEA-GLM — "LLMs as Zero-shot Graph Learners: Alignment of GNN Representations with LLM Token Embeddings"** (Wang, Zuo, Li, Wu; NeurIPS 2024). LLM: Vicuna-7B-v1.5 frozen; 2-layer GraphSAGE pretrained contrastively to align with LLM token embeddings, then fixed; only a linear projector → K graph tokens (K ∈ {1,3,5,10} tested). 8 datasets (Arxiv, PubMed, Cora-expanded, Children, History, Computer, Photo, Sports). Zero-shot PubMed 0.848 vs LLaGA 0.793 vs Vicuna 0.719; cross-task link-pred AUC Arxiv 0.657 vs LLaGA 0.570. Efficiency claimed qualitatively (titles only, central-node tokens only, linear projector). — [arXiv abs](https://arxiv.org/abs/2408.14512); [arXiv HTML](https://arxiv.org/html/2408.14512v3); [NeurIPS 2024 PDF](https://proceedings.neurips.cc/paper_files/paper/2024/file/0b77d3a82b59e9d9899370b378087faf-Paper-Conference.pdf)
- **GraphPrompter — "Can we Soft Prompt LLMs for Graph Learning Tasks?"** (Liu, He, Tian, Chawla; WWW 2024 short). Frozen LLM (Llama-2 cited as backbone **[size unverified]**) used as "robust feature extractor"; GNN output concatenated with text embeddings as soft prompt; datasets Cora, Citeseer, PubMed, ogbn-arxiv, ogbn-products; GAT baseline; reports PubMed top accuracy 94.80 %. — [arXiv abs](https://arxiv.org/abs/2402.10359)
- **GNP — "Graph Neural Prompting with Large Language Models"** (Tian et al.; AAAI 2024). FLAN-T5 3B and 11B; GAT encoder on retrieved KG subgraph (ConceptNet / UMLS), cross-modality pooling, domain projector → soft prompt prepended; DistMult link-prediction auxiliary loss. Six QA datasets (OBQA, ARC, PIQA, RiddleSense, PubMedQA, BioASQ). **Frozen LLM: +13.5 % avg; with LoRA: +1.8 %**; LoRA+GNP matches/beats full fine-tuning in 10/12 settings; flattening KG triples into text (KAPING-style) often *lowered* accuracy with a frozen LLM. — [arXiv abs](https://arxiv.org/abs/2309.15427); [arXiv HTML](https://arxiv.org/html/2309.15427v2)
- **HiGPT — "HiGPT: Heterogeneous Graph Language Model"** (Tang et al.; KDD 2024). In-context heterogeneous graph tokenizer + heterogeneity-aware instruction tuning + Mixture-of-Thought augmentation; LLM size / numbers not on the abstract page **[details unverified]**. — [arXiv abs](https://arxiv.org/abs/2402.16024)

**XATTN (cross-attention adapter between graph model and LLM)**

- **GraphTranslator — "GraphTranslator: Aligning Graph Model to Large Language Model for Open-ended Tasks"** (Zhang et al.; arXiv Feb 2024; WWW 2024 **[unverified]**). Frozen ChatGLM2-6B (28 blocks, hidden 4096) + frozen 2-layer GraphSAGE; *Translator* = BERT-base with 12 layers, cross-attention between node embeddings and 32 learnable query tokens (dim 768), then a linear map into LLM word-embedding space. Datasets: Taobao (~980k users) and ArXiv (169,343 nodes). Zero-shot ArXiv top-1 28.48 % vs best text baseline (ChatGLM2 + node text + neighbor text) 17.90 %; top-5 39.87 % slightly below LLM+node-text 42.46 %. No param count. — [arXiv abs](https://arxiv.org/abs/2402.07197); [arXiv HTML](https://arxiv.org/html/2402.07197v4)
- **MolCA — "MolCA: Molecular Graph-Language Modeling with Cross-Modal Projector and Uni-Modal Adapter"** (Liu et al.; EMNLP 2023 main). Q-Former cross-modal projector between a graph encoder and an LM (Galactica), LoRA uni-modal adapter; molecule captioning / IUPAC / retrieval. Sizes and numbers not on abstract page **[unverified]**. — [arXiv abs](https://arxiv.org/abs/2310.12798)

**PREFIX-KV (graph prefix injected at every attention layer)**

- **GraphLLM — "GraphLLM: Boosting Graph Reasoning Ability of Large Language Model"** (Chai, Zhang, Wu, Han, Hu, Huang, Yang; arXiv Oct 2023, preprint). LLaMA-2 7B (main) and 13B; a ~0.05B textual transformer encoder-decoder turns each node's text into a vector; a graph transformer with relative random-walk positional encodings learns structure; a linear projection yields a **5-token prefix prepended to keys and values at every attention layer** (prefix-tuning); zeroing the projection recovers vanilla prefix tuning. 0.0933B tunable params. Tasks: substructure counting, max triplet sum, shortest path, bipartite matching. GraphLLM 98.19 % avg exact match vs 47.35 % best Graph2Text (adjacency/edge-list text with zero-/few-shot/CoT/LoRA/prefix); context −96.45 %; inference 3.42× faster on substructure counting. — [arXiv abs](https://arxiv.org/abs/2310.05845); [arXiv HTML](https://arxiv.org/html/2310.05845v1)

**SIDE (per-layer side branch / interleaved GNN)**

- **ENGINE — "Efficient Tuning and Inference for Large Language Models on Textual Graphs"** (Zhu, Wang, Shi, Tang; IJCAI 2024). LLaMA2-7B **frozen** (e5-large in appendix); a lightweight **G-Ladder GNN attached to every LLM layer** (GraphSAGE chosen; GCN/GAT comparable); gradients flow only in the side structure, so hidden states can be cached. 7 datasets: Cora, CiteSeer, WikiCS, OGBN-ArXiv, ArXiv-2023, OGBN-Products (subset), Ele-Photo. 17 baselines incl. GCN/SAGE/GAT, GraphFormers, NodeFormer, fine-tuned BERT/SBERT/DeBERTa, GIANT, GLEM, TAPE, SimTeG, LoRA, IA3, Prompt Tuning, LST. OGBN-ArXiv cost table: ENGINE 3.91M trainable params, 14.9 GB, 4h23m; **ENGINE w/ caching 3.3 GB, 21 min (≈12× faster)**; LoRA-LLaMA2-7B 4.36M params, 44.8 GB, 10h18m; SimTeG 25h22m; GIANT 114.5M params, 29h44m. Accuracy: Cora 91.48 (SimTeG 88.04), CiteSeer 78.46, WikiCS 81.56, Arxiv 76.02 (SimTeG 75.29), ArXiv-2023 79.76, Products 80.05 (TAPE 79.76), Ele-Photo 83.75. Early exit: up to 5× faster inference, >90 % samples exit at layer 5, max accuracy drop 1.17 %. Ablation: removing message passing drops Cora 91.48 → 76.94. — [arXiv abs](https://arxiv.org/abs/2401.15569); [arXiv HTML](https://arxiv.org/html/2401.15569v2)
- **GOFA — "GOFA: A Generative One-For-All Model for Joint Graph Language Modeling"** (Kong, Feng, Liu, Huang, Huang, Chen, Zhang; arXiv Jul 2024, labeled ICLR'25 by Awesome-Graph-LLM). Mistral-7B with an ICAE-style compressor/decoder; randomly initialised modified TransformerConv GNN layers **inserted between transformer layers, only among the last few layers** ("first and last layer are always transformer layers"), gated by tanh initialised at 0; only GNN weights updated in pre-training (ICAE uses a LoRA adapter on the compressor). Pretrain: MAG240M, PubMed, Arxiv, Wikikg90mv2, WikiGraph, UltraChat200k. Zero-shot: Cora 70.81 vs 69.53 best baseline; Products 71.17 vs UniGraph 43.45; WikiCS 85.73 below UniGraph 89.74; perplexity 21.34 vs Mistral 30.12. No trainable-param/cost figures found. — [arXiv abs](https://arxiv.org/abs/2407.09709); [arXiv HTML](https://arxiv.org/html/2407.09709v2); [Awesome-Graph-LLM listing](https://raw.githubusercontent.com/XiaoxinHe/Awesome-Graph-LLM/main/README.md)

**OUTPUT (fusion at final hidden state)**

- **GraphAdapter — "Can GNN be Good Adapter for LLMs?"** (Huang, Han, Yang, Bao, Tao, Chai, Zhu; WWW 2024). Llama-2-13B default (also GPT-2 1.5B, RoBERTa-large), **frozen**; 2-layer GraphSAGE adapter; the LM's final hidden state per token is concatenated with the GNN node embedding → 2-layer MLP; residual averaging of LM-only and fused next-token probabilities; **GNN only at the final layer so transformer outputs can be cached**. Pretrain = next-token prediction on node text; fine-tune = prompt + linear head. Datasets: ogbn-arxiv, Instagram (11,339 nodes), Reddit (33,434). Trainable params ≈3M pretrain / 2M fine-tune vs GIANT 110M, GLEM 139M (claims ~30× fewer). Arxiv: GraphAdapter 0.7707 vs TAPE 0.7672 vs GLEM 0.7355; Instagram ROC-AUC 0.6513; Reddit 0.6461. Training on one A800: ≈505 min total (192 preprocessing, 312 pretraining, 1 fine-tune) vs GIANT 342, GLEM 612. — [arXiv abs](https://arxiv.org/abs/2402.12984); [arXiv HTML](https://arxiv.org/html/2402.12984)

**POS + ATTN-MASK inside an encoder LM (the direct ancestor of the 2026 decoder-side work)**

- **Graph Language Models** (Plenz & Frank; ACL 2024). T5 small/base/large encoder, initialised from the pretrained LM; KG turned into a Levi graph whose concept/relation tokens are individual nodes; **relative positional encoding = hop distance along graph paths, reusing T5's relative-position parameters**; two masks: ℓGLM (local; attention only within a triplet, information spreads across layers like message passing) and gGLM (global; any token attends to any token, undefined pairs initialised with T5's "far-away" bucket). Text/graph interleaving via extra text↔graph buckets. Linear probing (frozen) vs fine-tuning. ConceptNet relation classification: linear probe radius-5 gGLM 59.5 % vs T5-list (linearised triples) 55.3 %; with masking (r4,m1) 41.8 % vs 20.3 %; fine-tuned 65.3 vs 64.0 and 48.0/47.9 vs 40.4. Wikidata/REBEL KG population: gains small at full data (85.28 vs 85.36 macro-F1 relation score) and larger in low-data regimes. Graph transformers of the same architecture trained from scratch perform worst. Efficiency: same complexity as base LM; ℓGLM could exploit sparsity. — [arXiv abs](https://arxiv.org/abs/2401.07105); [arXiv HTML](https://arxiv.org/html/2401.07105v3)

**Encoder-LM + GNN fusion lineage (2021–2023)**

- **QA-GNN** (Yasunaga, Ren, Bosselut, Liang, Leskovec; NAACL 2021): LM relevance scoring of KG nodes + joint graph containing the QA-context node, updated with a GNN; CommonsenseQA, OpenBookQA, MedQA-USMLE; abstract gives no numbers. — [arXiv abs](https://arxiv.org/abs/2104.06378)
- **GreaseLM** (Zhang, Bosselut, Yasunaga, Ren, Liang, Manning, Leskovec; ICLR 2022): seeded with RoBERTa-Large (AristoRoBERTa for OpenBookQA, SapBERT for MedQA); LM layer and GNN layer run in parallel and after each layer an *interaction token* (LM side) and *interaction node* (GNN side) are concatenated and mixed by a "MInt" unit; **M = 5 GreaseLM layers** best (M=4 77.7, M=6 78.0, M=7 76.2 on CSQA dev); the paper states T5-3B and the 11B model are "8× and 30× larger than our model" and that GreaseLM outperforms them. — [arXiv abs](https://arxiv.org/abs/2201.08860); [arXiv PDF](https://arxiv.org/pdf/2201.08860)
- **DRAGON** (Yasunaga et al.; NeurIPS 2022): bidirectional LM–KG fusion pre-trained with MLM + KG link prediction; ≈+5 % absolute avg over LM and LM+KG models, +10 % on long-context / multi-step questions, +8 % low-resource OBQA/RiddleSense. — [arXiv abs](https://arxiv.org/abs/2210.09338)
- **Patton** (Jin et al.; ACL 2023): GraphFormers "GNN-nested Transformer" initialised from BERT / SciBERT, neighbour virtual token [n_CLS] and asymmetric multi-head attention; pretraining = network-contextualised MLM + masked node prediction; datasets MAG-Mathematics/Geology/Economics, Amazon-Clothes/Sports. — [arXiv abs](https://arxiv.org/abs/2305.12268); [arXiv PDF](https://arxiv.org/pdf/2305.12268)

**LLM-as-encoder / LLM-as-enhancer (no architectural fusion; included for the baseline landscape)**

- **GLEM** (Zhao et al.; ICLR 2023): variational EM alternating LM and GNN updates, motivated by avoiding joint LM+GNN training on big graphs. — [arXiv abs](https://arxiv.org/abs/2210.14709)
- **TAPE** (He, Bresson, Laurent, Perold, LeCun, Hooi; ICLR 2024): LLM explanations → LM interpreter → GNN features; Cora, PubMed, ogbn-arxiv, tape-arxiv23; "2.88× training-speed improvement over the closest baseline on ogbn-arxiv". — [arXiv abs](https://arxiv.org/abs/2305.19523)
- **SimTeG** (Duan et al.; arXiv 2023): supervised PEFT of a LM, then any GNN on the embeddings; node classification and link prediction. — [arXiv abs](https://arxiv.org/abs/2308.02565)
- **InstructGLM — "Language is All a Graph Needs"** (Ye, Zhang, Wang, Xu, Zhang; EACL 2024): natural-language description of multi-scale neighbourhoods, instruction-tuned Flan-T5-base/large and Llama-v1-7B with LoRA (18M trainable params); claims to surpass all GNN baselines on ogbn-arxiv, Cora, PubMed (table shows e.g. Llama-7b 75.70 ± 0.12 and Flan-T5-large 74.67 ± 0.08 — **columns unverified**). — [arXiv abs](https://arxiv.org/abs/2308.07134); [arXiv PDF](https://arxiv.org/pdf/2308.07134)
- **GraphText** (Zhao et al.; arXiv 2023 preprint): graph-syntax tree → text; training-free ChatGPT in-context reasoning claimed to match/exceed supervised GNNs. — [arXiv abs](https://arxiv.org/abs/2310.01089)

### Inferences
- Across the 2024 cohort, "efficiency" almost always means *trainable parameters relative to a frozen 7B LLM*; only ENGINE (12× training speedup via caching, 5× inference via early exit), GraphLLM (−96 % context, 3.42× inference) and G-Retriever (−99 % tokens via retrieval) quantify compute/token efficiency, and none measure data efficiency except Plenz & Frank (low-data regime) and GNP (frozen vs LoRA).
- The G-Retriever table is the cleanest 2024 three-way comparison (GraphToken soft-token vs LoRA on textualised graph vs both): on WebQSP LoRA-on-text (66.03) beats GraphToken (57.05), and the soft-token-only method only wins when combined with the textualised graph (70.49) — foreshadowing the 2025–2026 "token collapse" critique (KQ3).

- LLaGA ICML-2024, G-Retriever NeurIPS-2024, GraphTranslator WWW-2024 venues were not confirmed on the fetched arXiv pages (they are widely cited as such).
- GraphToken trainable-parameter total is inconsistent in the HTML extraction (17k–199k encoder vs ~11M head); the exact total needs the paper's Table.
- HiGPT and MolCA: only abstract pages were fetched; LLM sizes and numbers are missing.

## Key Question 2: What appeared in 2025–2026, especially methods that modify a decoder LLM's attention (bias / mask / RoPE / value path / weights), and "small LLM + graph ≈ large LLM" claims

### Takeaway
2025–2026 saw a clear shift from input-level soft tokens to **inside-the-attention** injection of graph structure into decoder LLMs: learned Graphormer-style attention biases (GTLM, Learnable Graph PE), training-free inverse-distance biases (GaLA, KDD'26), graph-masked attention + shared/reset RoPE positions (Graph-KV NeurIPS'25, NAG, UniGTE NeurIPS'25, GTLM), training-free attention redistribution (SLASH, LoReC), graph-conditioned LoRA weights (GaRA ICML'26), and mid-layer gated fusion (GaLoRA). These methods typically run on 0.6B–8B models and claim 0.015 %–2 % trainable parameters, O(N) instead of O(E) context, or zero training; several report that gains are largest on *small* backbones, but no paper claims a small graph-augmented LLM matches a specific larger text-only LLM.

### Cited Findings

**ATTN-BIAS + POS (learned, trained with LoRA)**

- **GTLM — "Teaching LLMs to See Graphs: Unifying Text and Structural Reasoning"** (Dario Vajda, Univ. Ljubljana / Cambridge; arXiv 2605.10247, v2 listed 2 Oct 2026; no venue). Base: **Llama-3.2-1B** (frozen) + LoRA (rank 16–32, ≈2 % of params) + structural bias params; Llama-3.1-8B for WebQSP/CWQ/ChEBI-20; BLOOM-1b1 (ALiBi) and Gemma-3-1B (dual RoPE) in appendix. **No GNN**: each node's tokens are concatenated; three biases added to raw attention logits in every layer/head, defined at node-pair level and broadcast to token pairs — SPD lookup table (max hop 8, 4,096 params), RRWP (K=16 random-walk probabilities → per-layer MLP, 50,688 params), Magnetic-Laplacian eigenfeatures (118,272 params); total **173,056 structural params ≈ 0.015 % of 1B**; bias is zero within a node so intra-node attention equals the pretrained LLM; context nodes form a bidirectional PrefixLM block, target node is causal; **RoPE position ids reset to 0 at each node start** → provable prefix-node permutation equivariance and exact reduction to the base LLM for single-node inputs (logit diff ≈2e-5). Datasets: GraphQA; TAG node classification Cora / PubMed / OGBN-Arxiv / Reddit (labels generated as text); WebQSP & CWQ (SR subgraphs as Levi graphs); MoleculeNet BACE/BBBP/HIV + ChEBI-20 captioning; needle-in-a-graph. Baselines: zero-shot LLM, GraphToken variants; GCN/GraphSAGE/GAT/NodeFormer/GRACE/GraphText/GraphGPT/LLaGA/RGLM; RoG/GNN-RAG/SubgraphRAG; Uni-Mol/MolCA/InstructMol/MolT5 etc.; and a same-budget flat-text LLM. Results: GraphQA node count 100 %, edge count 56.9 %, cycle check 96.7 %, shortest path 92.7 %; Cora 90.04 acc / PubMed 94.70 / OGBN-Arxiv 76.53 / Reddit 68.09; WebQSP (8B) F1 77.9 vs GNN-RAG-on-SR 69.8; CWQ F1 62.1 vs 53.3; BACE 82.0 / BBBP 70.6 / HIV 76.9 ROC-AUC; ChEBI-20 BLEU-2 0.534 (1B) / 0.572 (8B) vs InstructMol-GS 0.475; needle-in-a-graph (N=128, k=4) 98.0 % vs LLM 8.5 %. Bias ablation (GraphQA): removing Magnetic bias drops edge count 57.2 → 8.9; SPD removal within seed noise. **Text-only-variant ablation (Table 19)**: Cora 86.78 → 88.99, PubMed 93.98 → 94.57 (small), WebQSP F1 48.5 → 73.5 and GraphQA mean 33.2 → 85.7 (large). Scaling 1B→8B: classification changes ≤0.3 pp (not significant), generation gains (CWQ Hit +10.8 pp). Cost: FlexAttention score_mod ≈2× a FlashAttention LLM per step at same peak memory, 2–10× faster than eager; OGBN-Arxiv epoch 50.7 h → 5.3 h; TAG runs 6–8 h on one H100, Arxiv ≈20 h. Mean tokens/graph: Cora 663, PubMed 950, Reddit 976, Arxiv 1,065. — [arXiv HTML](https://arxiv.org/html/2605.10247)
- **"Scaling Graph Reasoning in Language Models with Learnable Graph Positional Encodings"** (Porras-Valenzuela, Arora, Ribeiro; arXiv 2610.27439, Oct 2026). A GNN followed by a Graph Transformer computes permutation-equivariant positional encodings that **modulate attention logits** of an LRM trained with LoRA; a post-fusion module feeds structure into hidden states; serialized adjacency removed → **context O(N)** instead of growing with |E|; trained on small graphs with solver labels, evaluated up to 1,000 nodes; baseline = conventional LRM with serialized graph. LLM size, datasets, numbers not on abstract page **[unverified]**. — [arXiv abs](https://arxiv.org/abs/2610.27439)

**ATTN-BIAS (training-free, inference-time)**

- **GaLA — "Formalizing and Mitigating Structural Distortion in LLM Attention for Graph Reasoning"** (Loveland, Trivedi, Weinstein, Huang, Koutra; **KDD 2026**, DOI 10.1145/3770855.3818097; arXiv 2606.15633). Frozen Qwen2.5-3B-Instruct, Ministral-3B-Instruct, Qwen2.5-7B-Instruct. Adds λ_h·B_ij to pre-softmax logits where B_ij = 1/shortest-path-distance between the graph nodes owning tokens i and j (0 if unreachable), **only in early layers l ∈ [0, L/2]**; per-head strength from a one-time calibration (label-free attention-entropy variant, or one backward pass gradient score), global β tuned on 200 validation nodes. Motivation: RoPE decay distorts structure when graphs are linearised. Tasks: semi-synthetic majority-neighbour-label on 2-hop subgraphs of Cora/PubMed/Arxiv and real node classification; baselines random/BFS linearisation, CoT-256/512, GraphICL, fine-tuning upper bound. Gains: semi-synthetic Cora Ministral-3B BFS 69.3 → 87.9 (+18.6 pp); Qwen2.5-3B 83.3 → 90.4; real PubMed Qwen2.5-3B 77.5 → 82.5 (+5.0 pp); beats GraphICL by 4.7–13.5 pp on Qwen2.5-3B. - **SLASH — "SLASH the Sink: Sharpening Structural Attention Inside LLMs"** (Liu, Lu, Wang, Zhou, Jin; arXiv 2605.10503, May 2026). Training-free; observes a "sawtooth" attention pattern aligned with the token-level adjacency matrix that the attention sink dilutes; rescales sink attention by γ and redistributes mass to non-sink tokens in heads/layers selected offline by entropy + adjacency-concentration score (layer-level intervention more stable than head-level). Models: Llama-3.2-3B, Llama-3.1-8B, Qwen3-4B/8B/14B, GraphWiz-Mistral-7B, GraphWiz-LLaMA2-7B/13B, MolecularGPT. Appendix: Cora Qwen3-8B 0.329 → 0.600. Overhead: no params; ≈10 calibration runs; **needs full attention matrix → incompatible with FlashAttention** (Llama-3.1-8B 4-bit, 6,942 tokens: 36.1 GB eager vs 13.3 GB FA2). — [arXiv HTML](https://arxiv.org/html/2605.10503v3)
- **LoReC — "LoReC: Rethinking Large Language Models for Graph Data Analysis"** (Zhan et al.; arXiv 2604.17897, Apr 2026). Plug-and-play decoding on top of GraphGPT (Vicuna-7B) and GraphPrompter (Llama2-7B, Qwen3-8B): *Look* boosts pre-softmax attention logits of graph tokens by η when next-token entropy > γ (layers 15–22); *Remember* mixes a graph-memory output (graph tokens as K/V) into **FFN layers 8–16** with α = 0.25; *Contrast* corrects logits using graph-masked and edge-perturbed passes. Datasets Cora, Citeseer, PubMed, ogbn-arxiv, ogbn-products. Gains up to +2.58 pp acc over GraphGPT and +5.12 pp over GraphPrompter (macro-F1 +4.24 / +7.97); claims to beat GNN baselines. Cost: 82.69 ms/token vs 45.23 (GraphPrompter) vs 13.67 (Qwen3-8B); memory 27.93 vs 18.43 GB. — [arXiv HTML](https://arxiv.org/html/2604.17897); [arXiv abs](https://arxiv.org/abs/2604.17897)

**ATTN-MASK + POS (graph-sparsified attention with shared / reset positions)**

- **Graph-KV — "Graph-KV: Breaking Sequence via Injecting Structural Biases into Large Language Models"** (Wang, Wang, Li, Liu, Miao, Wang, Li; Georgia Tech / UT Austin; arXiv 2506.07334, v2 Jan 2026; **NeurIPS 2025** per Semantic Scholar venue field). Llama-3.1-8B "8B-Block" (post-trained with independent attention blocks on tulu-3 + 20k RAG instances); each text chunk encoded independently into a KV cache; a target chunk **attends only to the KV caches of its graph-source chunks** (one propagation round); **all source chunks share one position range, targets the next range** → positional span ≈ T·L instead of n·L. Complexity O(|V|L²)+O(|E|L²) vs sequential O(n²L²). Tasks: 7 RAG datasets (bipartite top-m graph), new Arxiv-QA (citation neighbourhoods, up to ≈264.6k tokens), Cora/PubMed topic classification via references. Benchmarks: 9 GraphQA-style tasks (180k graphs) + ExplaGraphs / SceneGraphs / WebQSP. - **UniGTE — "UniGTE: Unified Graph-Text Encoding for Zero-Shot Generalization across Graph Tasks and Domains"** (Wang, Zuo, Lu, Wu; **NeurIPS 2025**; arXiv 2510.16885). ### Inferences
- The 2026 "native" designs (GTLM, NAG, UniGTE, Graph-KV) converge on the same two primitives Plenz & Frank used in T5 in 2024 — graph-distance-indexed relative attention terms and block/graph masks — but now realised in RoPE decoders by (a) resetting or sharing position ids per node and (b) adding per-node-pair biases broadcast to tokens, which keeps the pretrained intra-node computation intact and makes exact-reduction/equivariance proofs possible.
- Training-free attention interventions (GaLA, SLASH, LoReC) show that a frozen 3B–8B model already encodes recoverable topology; however, SLASH and GTLM both note the FlashAttention incompatibility / 2× step cost of custom attention, so "parameter efficiency" is traded for kernel efficiency.
- On the "small LLM + graph matches larger LLM" question, the strongest evidence is indirect: GTLM finds 1B saturates classification (8B only helps generation); GaLA's gains shrink from 3B to 7B; GaLoRA (124M GPT-2) approaches GraphAdapter-Llama-2-13B on two of three datasets; NAG uses 0.6B against an 8B zero-shot reference. None of these is a controlled "small+graph vs large text-only" comparison.

- Semantic Scholar rate-limited the cited-by queries for LLaGA (2402.08170), Plenz & Frank (2401.07105), ENGINE (2401.15569) and GraphAdapter (2402.12984); only GraphToken's 160 citers were enumerated.

## Key Question 3: Papers that explicitly compare "GNN encoder → LLM" vs "graph serialised as text → LLM" vs "LLM text-only", and cases where structure did NOT help

### Takeaway
Five 2025–2026 studies independently find that on text-attributed-graph benchmarks the structural channel contributes little or nothing: center-node-text-only or MLP adapters match or beat GNN adapters and neighbourhood templates (Xu et al. 2025), soft-prompted LLMs match full-GNN GLMs (CLEGR 2025), G-Retriever's graph token has collapsed to a near-constant vector and the verbalised graph carries the signal (Di Francesco et al. 2026), text-only ablations of GTLM lose <2.2 pp on Cora/PubMed but 25–50 pp on WebQSP/GraphQA, and LLMNodeBed (ICML 2025) shows LLM-as-encoder (ENGINE) ≈ GNN→LLM (LLaGA) while text-only instruction tuning is clearly worst. Structure matters when the *question is about structure* (GraphQA, KGQA, heterophily, OOD size) and when text is weak.

- **G-Retriever (2024)**: soft-token-only GraphToken 57.05 Hit@1 on WebQSP < LoRA on textualised graph 66.03 < G-Retriever (token + text) 70.49; removing textualised graph from G-Retriever −19.2 %, removing graph encoder −22.5 %. — [arXiv HTML](https://arxiv.org/html/2402.07630v3)
- **NAG (2026)**: against Qwen3-LoRA on serialised text, graph-aware attention wins 8/9 topological tasks but on SceneGraphs by only 0.11 pp (83.82 vs 83.71); GraphToken-E (GNN soft tokens) 80.51 on ExplaGraphs vs NAG-LoRA 82.49. — [arXiv HTML](https://arxiv.org/html/2601.22657)
- **"Less is More" (2025)**: LoRA on serialised text generalises OOD far better than GNN soft tokens (DFS .992 vs .254 at 140–160 nodes); adding edge text to graph tokens recovers part of the gap (cycle graphs .700 → .867). — [arXiv HTML](https://arxiv.org/html/2508.10115v1)
- **GNP (AAAI 2024)**: with a frozen FLAN-T5, flattening KG triples into text (KAPING) often *lowered* accuracy while the GNN soft prompt gave +13.5 %. — [arXiv HTML](https://arxiv.org/html/2309.15427v2)
- **Plenz & Frank (ACL 2024)**: structure-aware attention beats linearised-triple T5 most when parts of the graph are masked (41.8 vs 20.3) and in low-data regimes; at full REBEL data differences vanish (85.28 vs 85.36). — [arXiv HTML](https://arxiv.org/html/2401.07105v3)
- **ENGINE ablation**: removing structural message passing drops Cora 91.48 → 76.94 (structure helps when the LLM is used as encoder with a GNN ladder). — [arXiv HTML](https://arxiv.org/html/2401.15569v2)
- **Attention-mechanisms ICML'25**: disrupting graph connectivity in serialised inputs "barely hurt most datasets" except Roman-Empire. — [arXiv HTML](https://arxiv.org/html/2505.02130)
- **GraphICL** (Sun et al.; arXiv 2501.15755): structured prompts on general LLMs "outperform state-of-the-art specialized graph LLMs" in resource-constrained and out-of-domain settings (no numbers on abstract page). — [arXiv abs](https://arxiv.org/abs/2501.15755)
- **GaLA (KDD'26)**: on Qwen2.5-3B beats GraphICL by 4.7–13.5 pp, i.e., attention-level bias > prompt-level structure on the same frozen model. — [arXiv HTML](https://arxiv.org/html/2606.15633v2)
- **"Actions Speak Louder than Prompts"** (Finkelshtein, Cucerzan, Jauhar, White; arXiv 2509.18487): across citation/web/e-commerce/social graphs, LLM-as-code-generator beats prompting and tool use, especially when serialised neighbourhoods exceed the token budget. — [arXiv abs](https://arxiv.org/abs/2509.18487)
- **"Rethinking and Benchmarking LLMs for Graph Reasoning"** (Hu et al.; arXiv 2509.24260): GPT-4o-mini with "reason-then-code" reaches near-perfect accuracy on existing graph-reasoning benchmarks, suggesting GraphQA-style benchmarks saturate without any architectural change. — [arXiv abs](https://arxiv.org/abs/2509.24260)

### Inferences
- Where structure did NOT help: homophilic TAG node classification with rich text (Xu et al.; GTLM Table 19; LLMNodeBed supervised), heterophilic graphs with LLaGA-style templates (Xu et al. School), full-data KG population (Plenz & Frank), and GraphQA-style tasks once reason-then-code is allowed (Hu et al.). Where it DID help: structure-centric questions (GraphQA, WebQSP/CWQ, needle-in-graph), label-scarce semi-supervised TAGs (LLMNodeBed), OOD graph size (only when structure enters via attention/positional terms rather than pooled soft tokens), and small frozen models (GaLA, SLASH).
- The recurring methodological flaw identified in 2025–2026 is that pooled single-token soft prompts (GraphToken/G-Retriever family) can be replaced by a constant vector without loss; therefore any new method should report the "learned constant token" and "verbalised-graph-only" controls that Di Francesco et al. and Xu et al. introduced.

### Gaps
- No paper was found that runs the full 3-way comparison (GNN soft tokens vs serialised text vs text-only) *and* an attention-level injection on the same backbone and datasets; GTLM comes closest but lacks a GNN-soft-token arm on TAGs, NAG lacks TAG datasets, and Xu et al. lack attention-level methods.
- CLEGR benchmark numbers and the exact GLMs evaluated were not extracted (abstract only).

## Key Question 4: Systematic ablations of the injection point (input vs mid-layer vs attention-level) under matched parameter budgets

### Takeaway
No paper found performs a clean, budget-matched sweep across *input soft tokens vs mid-layer side branch vs attention bias*. The closest evidence is single-axis: GaRA's depth sweep (layer 21 of 32 best, drop near output), GreaseLM's M-layer sweep (M=5 best), GaLA's early-layer-only choice, LoReC's FFN 8–16 / attention 15–22 ranges, GOFA's "last few layers" interleaving, ENGINE's early-exit at layer 5, GaLoRA's reasoned (untested) layers 5–7/9–11, GTLM's bias-type ablation, NAG's position-recalibration ablation, and Di Francesco et al.'s matched-budget encoder/projector comparison.

### Cited Findings
- **GaRA (ICML 2026)**: weight-level injection sweep over layers {1, 11, 21, 31, 32} of Vicuna-7B — accuracy rises from shallow to intermediate layers and falls near the output (layer 21 best); authors attribute the late-layer drop to updates bypassing most of the backbone. Weight-level injection still needs input-level subgraph prompts. — [arXiv HTML](https://arxiv.org/html/2606.22429v1)
- **GaLA (KDD 2026)**: bias applied only to layers [0, L/2]; justified by RoPE-decay theory; no layer sweep in visible text (Appendix D head-selection not extracted). — [arXiv HTML](https://arxiv.org/html/2606.15633v2)
- **SLASH (2026)**: structurally active heads "cluster in intermediate layers"; layer-level intervention more stable than head-level. — [arXiv HTML](https://arxiv.org/html/2605.10503v3)
- **LoReC (2026)**: attention amplification layers 15–22, FFN re-injection layers 8–16 (configuration, not a sweep). — [arXiv HTML](https://arxiv.org/html/2604.17897)
- **GreaseLM (ICLR 2022)**: number of fusion layers M=4: 77.7, M=5 best, M=6: 78.0, M=7: 76.2 (CSQA dev). — [arXiv PDF](https://arxiv.org/pdf/2201.08860)
- **GOFA**: GNN layers inserted "only among the last few layers", first and last always transformer layers; gate initialised at 0. — [arXiv HTML](https://arxiv.org/html/2407.09709v2)
- **ENGINE**: dynamic early exit — >90 % of samples exit at the 5th ladder layer with ≤1.17 % accuracy loss, implying most structural signal is captured in early side layers. — [arXiv HTML](https://arxiv.org/html/2401.15569v2)
- **GaLoRA**: 1-hop into layers 5–7, 2-hop into layers 9–11 of 12; explicitly "no ablation" of injection point. — [arXiv HTML](https://arxiv.org/html/2603.10298)
- **GTLM**: ablates bias *type* (Magnetic ≫ RRWP > SPD on GraphQA edge count 57.2 → 8.9 without Magnetic) and text-only vs biased; no layer-subset or bias-vs-mask-vs-RoPE-only ablation found in the fetched text. — [arXiv HTML](https://arxiv.org/html/2605.10247)
- **NAG**: ablates recalibrated vs sequential position ids (+2.95 pp connected nodes, −0.5 pp ExplaGraphs) and sparse vs full query-graph mask ("neither wins consistently"). — [arXiv HTML](https://arxiv.org/html/2601.22657)
- **GraphLLM (2023)**: the only early paper whose design nests input-level and per-layer injection — zeroing its graph projection reduces to vanilla prefix tuning, and the paper reports prefix tuning / LoRA / Graph2Text baselines (98.19 % vs 47.35 % best Graph2Text). — [arXiv HTML](https://arxiv.org/html/2310.05845v1)
- **Di Francesco et al. (2026)**: matched-budget comparison of projector designs (GELU vs original), encoder types (graph transformer / GAT / GCN) and frozen vs LoRA Llama-2-7B vs Qwen2.5-3B, but all at the input level. — [arXiv HTML](https://arxiv.org/html/2610.31572)
- **Position paper "How can Graphs Help LLMs?"** (Wang, Hu, Wang, Shi, Zhang; PKU/BUPT; arXiv 2605.02452, May 2026): characterises Graph-as-Text (no training, limited to graphs of "tens of tokens"), Graph-as-Embedding (trains encoder, "most scalable", compresses thousands of nodes into one vector) and Merging-GNN-into-LLM (GraphFormers, Patton, GOFA, CGM; "requires extensive pretraining", "only feasible with LLMs under about 10B", one token per node → hundreds of nodes); states performance is task-dependent, text-rich simple graphs favour Graph-as-Text while weak-text complex topology (molecules) favours embedding/merged. — [arXiv HTML](https://arxiv.org/html/2605.02452v1)

### Inferences
- The partial evidence agrees that *intermediate* layers are the best single place to inject structure into a decoder (GaRA layer 21/32, SLASH intermediate heads, GaLoRA mid layers, GreaseLM upper-middle M=5), while early-only (GaLA) works for training-free biasing and last-layer-only (GraphAdapter) is chosen for caching convenience rather than accuracy.
- A budget-matched three-arm study (input soft tokens vs mid-layer ladder vs per-layer attention bias, same backbone, same datasets incl. a structure-centric and a text-rich one, with the constant-token and text-only controls) does not yet exist and would be a clear contribution.

### Gaps
- Appendix D of GaLA and Appendix K/other appendices of GTLM beyond the fetched ranges may contain layer ablations not captured here.
- No paper reports injection-point results normalised by FLOPs or wall-clock; parameter counts are the only matched budget seen.

## Key Question 5: 2025–2026 surveys of LLM + graph and their taxonomies

### Takeaway
Newer surveys split along *where the integration happens* rather than by LLM role: Su et al. (Oct 2025) use "LLM for TAG" (sequential / parallel orchestration; structure-aware LMs; graph prompt tuning) vs "TAG for LLM" (embedding-based vs soft-prompt-based fusion; nested / RAG / graph-of-thought); Yu et al. (ACM TOIS 2025) use Graph2text vs Graph2token with node/pairwise/group/holistic token granularity; the 2026 PKU position paper uses Graph-as-Text / Graph-as-Embedding / Merging-GNN-into-LLM; and the 2024 role-based taxonomies (Jin et al. TKDE: Predictor/Encoder/Aligner; Li et al. IJCAI'24: Enhancer/Predictor/Alignment; Ren et al.: GNN-as-prefix / LLM-as-prefix / integration / LLM-only) remain the reference frames. None of the surveys yet has a category for attention-bias / positional-encoding injection into decoder LLMs.

### Cited Findings
- **"Large Language Models Meet Text-Attributed Graphs: A Survey of Integration Frameworks and Applications"** (Su, Wang, Wang, Zhang, Zhang, Pei; arXiv 2510.21131, 24 Oct 2025). Taxonomy: *LLM for TAG* → sequential orchestration (prompting; structure-agnostic vs structure-aware prompts; structure-aware LMs; MoE), parallel orchestration (two-tower; mutual pseudo-label supervision), pre-trained models for TAGs (TAG Transformers: PATTON, TextGT, GSPT, ENGINE, GIMLET, GraphFormers, JointGT, TGformer, TG-Transformer; graph foundation models; fine-tuning; graph prompt tuning). *TAG for LLM* → two-module (embedding-based fusion; soft-prompt-based fusion: LLaGA, GraphAdapter, TEA-GLM, Dr.E) and multi-module (nested; RAG; graph-of-thought). 2025 methods named: GraphLoRA, GraphMaster, AutoGFM, MDGFM, GLIP-OOD, LLM-BP, GraphEval, Dr.E, GraphGPT2 (Eulerian-path serialisation), EdgePrompt. No category for attention/positional injection. — [arXiv HTML](https://arxiv.org/html/2510.21131)
- **"Graph2text or Graph2token: A Perspective of Large Language Models for Graph Learning"** (Yu et al.; ACM Trans. Inf. Syst., DOI 10.1145/3786600; arXiv 2501.01124, Jan 2025). Two paradigms; four challenges (alignment, position, multi-level semantics, context); Graph2token sub-types Node2token (VQGraph, TokenGT, GraphGPT, GraphTranslator, GraphLLM, GIMLET, LLaGA, Graph-BERT, OpenGraph, HiGPT, UniGraph), Pairwise, Group-aware, Holistic. States token type/quality significantly affect LLM performance; a search snippet attributes to it the view that "model parameter adaptations may be more effective than prompt design" (not confirmed in fetched text). — [arXiv HTML](https://arxiv.org/html/2501.01124); [ACM DL](https://dl.acm.org/doi/10.1145/3786600)
- **"Position: How can Graphs Help Large Language Models?"** (Wang, Hu, Wang, Shi, Zhang; arXiv 2605.02452, May 2026): Graph-as-Text / Graph-as-Embedding / Merging-GNN-into-LLM; notes graph-RAG index construction costs 10–20× vector baselines. — [arXiv HTML](https://arxiv.org/html/2605.02452v1)
- **"A Survey of Large Language Models for Data Challenges in Graphs"** (formerly "Using LLMs to Tackle Fundamental Challenges in Graph Learning: A Comprehensive Survey"; Li et al., 14 authors; arXiv 2505.18475, May 2025, v2 Sep 2025; accepted Expert Systems with Applications 2026): organised by four data challenges (incompleteness, imbalance, cross-domain heterogeneity, dynamic instability). — [arXiv abs](https://arxiv.org/abs/2505.18475)
- **"Are Large Language Models Suitable for Graph Computation? Progress and Prospects"** (Zhang, Han, Wang, Ni, Bonifati, Zhang; arXiv 2606.06865, Jun 2026): LLMs-as-executors vs LLMs-as-planners; concludes LLMs are "promising for simple, small-scale tasks, but remain unreliable for large-scale and exactness-demanding tasks". — [arXiv abs](https://arxiv.org/abs/2606.06865)
- **"Graph Machine Learning in the Era of Large Language Models"** (Wang et al.; accepted ACM TIST; arXiv 2404.14928, v3 May 2026): LLMs-for-Graph-ML vs Graphs-for-LLMs. — [arXiv abs](https://arxiv.org/abs/2404.14928)
- **LLMNodeBed (ICML 2025)** functions as an empirical survey with categories LLM-as-Encoder / LLM-as-Explainer / LLM-as-Predictor / zero-shot GFM. — [arXiv HTML](https://arxiv.org/html/2502.00829v2)
- **Jin et al., "Large Language Models on Graphs: A Comprehensive Survey"** (IEEE TKDE 2024; v4 Nov 2024): pure / text-attributed / text-paired graphs × LLM as Predictor / Encoder / Aligner; the companion awesome-list further splits Predictor into Graph-as-Sequence, Graph-Empowered LLM, Graph-Aware LLM Finetuning. — [arXiv abs](https://arxiv.org/abs/2312.02783); [Awesome-Language-Model-on-Graphs](https://raw.githubusercontent.com/PeterGriffinJin/Awesome-Language-Model-on-Graphs/main/README.md)
- **Li et al., "A Survey of Graph Meets Large Language Model"** (IJCAI 2024 survey track; v4 Apr 2024): LLM as enhancer / predictor / alignment component. — [arXiv abs](https://arxiv.org/abs/2311.12399)
- **Ren et al., "A Survey of Large Language Models for Graphs"** (arXiv 2405.08011, v3 Sep 2024): GNNs as Prefix / LLMs as Prefix / LLMs–Graphs Integration / LLMs-Only. — [arXiv abs](https://arxiv.org/abs/2405.08011v1)
- **Chen et al., "Exploring the Potential of LLMs in Learning on Graphs"** (SIGKDD Explorations; arXiv 2307.03393, v4 Jan 2024): LLMs-as-Enhancers vs LLMs-as-Predictors. — [arXiv abs](https://arxiv.org/abs/2307.03393)
- **Awesome-list coverage check**: Awesome-Graph-LLM (XiaoxinHe) lists 2025 entries but no 2026 ones and no entry whose title mentions attention / positional encoding; Awesome-Language-Model-on-Graphs (Jin) lists only two 2025 entries and no 2026 entries — both lists lag the arXiv citation graph badly. — [Awesome-Graph-LLM](https://raw.githubusercontent.com/XiaoxinHe/Awesome-Graph-LLM/main/README.md); [Awesome-Language-Model-on-Graphs](https://raw.githubusercontent.com/PeterGriffinJin/Awesome-Language-Model-on-Graphs/main/README.md)

### Inferences
- A taxonomy that matches the 2025–2026 literature would add an explicit axis for *decoder-internal* injection: (i) input soft tokens, (ii) prefix-KV / per-layer side branch / interleaved GNN, (iii) attention-logit bias, (iv) attention mask + position-id recalibration, (v) weight-level (generated LoRA), (vi) training-free attention redistribution — plus the control arms (constant token, verbalised-graph-only, text-only) that the critique papers demand.

### Gaps
- Full taxonomy details of Su et al. Section 4 (TAG-for-LLM soft-prompt fusion) and Yu et al. Sections 6–7 (efficiency discussion) were beyond the fetched character range.
- No 2026 survey specifically on attention-level graph injection was found.
